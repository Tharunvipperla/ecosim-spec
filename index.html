ECOSIM — Technical Specification

ECOSIM — Technical Specification

Detailed design of the core components, data model, environmental model, multi-nutrient soil chemistry, balanced-reaction chemistry, algorithms, time/space complexity, and the full parameter set.

ECOSIM is an engine, not a game. It is a portable, deterministic ecosystem simulator (plus a UE5 plugin adapter). It has no player, no score, no UI, and no win condition, and it must never acquire one — that is what keeps it both a transferable plugin and a scientific instrument.

The god game is a separate product built on top of it — see GODGAME_DESIGN.md — and it talks to this engine only through the host API of 6.5. If a game feature cannot be expressed as a read or a write on that API, the answer is to extend the API deliberately, never to reach into the core.

Companions: ECOSIM_DESIGN.md (architecture & roadmap) · GODGAME_DESIGN.md (the game).

Notation: Nk = number of distinct nutrients (config value). The nutrient potassium is written K⁺ to avoid clashing with the count. G = grid cells, N = live agents, f = cells in a plant's footprint (small constant).

The five feedback loops that make the world self-regulate

Each one is marked in the graph. Only Loop 3 moves real mass (drawn solid); the other four only modulate rates (drawn dotted) — nothing physical travels along them.

#LoopWhat it doesKind
1Canopy → lightA plant's own leaves shade the ground beneath it, so growth suppresses its own future light supply.rate
2Roots → nutrientsRoots deepen and spread, reaching water and nutrients that were previously out of range.rate
3Death → soilA dead organism's carbon and nutrients return to the soil, and grow the next generation. This is the only loop where matter actually travels.mass
4Organic matter → soil capacityHumus raises the soil's ability to hold water and nutrients — so a thriving ecosystem builds its own soil, and a collapsing one degrades it.rate
5Litter quality → decayPoor-quality litter (high C:N) makes decomposers lock up soil nitrogen instead of releasing it, impoverishing the site further (2.5.1).rate

Reading the graph. Follow the spine top-to-bottom: time sets the climate → climate conditions the environment fields → plants draw fields into their reserves → metabolism turns reserves + light + gas into an energy budget → the budget becomes growth traits or stress/death → death feeds the decomposer loop that refills the soil → a biome-health node just observes the whole thing. To see what a variable depends on, read the arrows pointing into its node; to see what it affects, read the arrows leaving it. The arrow style tells you the kind of coupling (see the legend): the double-headed arrows are the only true two-way exchanges — an organism and its air cell trading CO₂/O₂ each tick (this triad is the O₂/CO₂ loop), and the decomposer pool both driving and being grown by decomposition. Everything solid single-headed is conserved mass or energy moving one way; everything dotted is a rate-control or a metric read, where nothing physical moves. The numbers 1–5 on the arrows mark the five self-regulating feedback loops listed above: loop 3 (death → decompose → soil) is drawn solid because real mass returns, while loops 1, 2, 4 and 5 are dotted because they only modulate rates — shade, root reach, soil building, and litter quality.

Three couplings deserve a second look, because they are the ones most models get wrong by omitting:

  • The stomatal knot (4J). Look at STOM: a single dial that simultaneously opens the door for CO₂ and lets water escape. This is the central trade-off of plant life, and notice that HGT feeds back into HYD — being tall is hydraulically expensive, which imposes a height limit entirely independent of the carbon budget.
  • The litter-quality loop — loop 5 (2.5.1). The arrow from ORGN back into SAPRO carries a sign flip: poor-quality (high C:N) litter makes decomposers take nitrogen out of the soil rather than release it. A stand can impoverish its own soil.
  • DIST (4L). It looks peripheral, but it is load-bearing: remove it and the whole graph settles into a single-species steady state. Diversity in this model is not a property of the species list; it is a property of the disturbance regime.

0.1The model in one page — equation run order

Every tick, in order. This order is part of the model definition, not an implementation detail — the scheme is explicit Euler with operator splitting, so reordering these steps changes the answer (8.2). Rates are stated per day and scaled by Δt (0.3.1).

  1. Climate/light (4A): sunlight = isDay·peakSunlight·sin(π·dayProgress).
  2. Light field (2.2): lightGround = sunlight·exp(−k·LAI).
  3. Soil derive (2.6): fieldCapacity, wiltingPoint, CEC_i = f(clay, organicCarbon); moistureAvail = clamp((water−wiltingPoint)/(fieldCapacity−wiltingPoint),0,1).
  4. Demand (3.2): availConc_i = nutrients[i]·pHFactor_i(pH); demand_i = Vmax_i·rootMass·availConc_i/(Km_i+availConc_i); water demand ×moistureAvail.
  5. Apportion (3.2.1): grant = demand·min(1, available/ΣdemandThisCell) → reserves[i], waterReserve.
  6. Growth limiter (3.3): nutrientFactor = min_i response_i(reserves[i]).
  7. Metabolism (4/4E): P = A·leafArea·f(lightGround,waterReserve,CO₂)·φ·captureEff (day, CO₂→O₂); respiration = maintenance·wood·Q10^((T−Tref)/10) (O₂→CO₂) — wood, not total carbon; foliage is charged by construction and turnover instead (4I.3).
  8. Net & allocation (3.4): net = photo − resp; if net>0, Δtrait = net·(W[trait]·reserves)/Σ and reserves→tissue; else stress += −net. Foliage is served first out of growth, up to targetLeafC (4I.2b).

8b. Leaf turnover (4I.2b): loss = leafC·(1−e^{−dt/leafLifespan}) → litter, with leafResorb of its nutrients withdrawn back to reserves first. This is litterfall from living plants — before it, the only route from plant carbon to soil carbon was death, and a forest floor is mostly made by trees still standing.

  1. Fate (4): stress > deathStressThreshold · B → Death (relative to biomass, 4.1a); Mature & energy>seedCost → seeds (inherit genome, 4B).
  2. Decomposition (2.5/4E): decompRate_eff = baseDecomp·decomposerActivity·f_moist·f_temp·f_pH·f_quality(C:N); carbon → CO₂; nutrients released or immobilized depending on litter C:N (2.5.1).
  3. Field update: diffusion (effLeach_i = nutrientDiffusion[i]·(1−CEC_i)), downhill flow (2.7), evaporation, drainage, gas mix + atmosphere pull, weathering source.
  4. Rollup (4F.2, every metricsEveryCycles): biomeHealth = Σ w·(indicators).

Interleaved with the above (each is O(N) or O(G), see 5):

  • Water relations inside step 7 — stomata g_s set both the CO₂ intake and the transpirational water loss; hydraulic tension can kill (4J).
  • Allocation inside step 8 — the split is skewed toward the scarcer resource (3.7).
  • Phenology each tick — accumulate GDD; budburst / leaf-drop / dormancy (4K).
  • Mycorrhizal transfer after step 8 — surplus carbon flows to sinks across the network (4M).
  • Disturbance as a rare event — fire, storm, drought, herbivory, pathogens (4L).
  • Conservation asserts at the end of the tick, in debug builds — carbon and every nutrient must balance (4C). This is the cheapest bug-detector in the project.

0.3Nomenclature, units & dimensional consistency

Every quantity in this document carries physical units. A model whose symbols are unitless numbers cannot be compared to data, calibrated against a field measurement, or checked for dimensional errors — so the units are normative, not decorative. If you implement a term whose units don't balance, the term is wrong.

0.3.1The time base (read this first — it is the most common source of error)

1 tick  = one atomic simulation step   (the integration timestep Δt)
tickHours   = 24 / ticksPerDay            // ticksPerDay = 24  →  1 tick = 1 sim-hour
Δt          = tickHours / 24  [day]       // the timestep expressed in DAYS
tickHz      = ticks executed per second of REAL wall-clock time (a playback speed,
              NOT a physical quantity — it never appears in any equation)

All rate parameters are stated per day and converted once at load: rate_perTick = rate_perDay · Δt. This decouples the physics from the playback speed: doubling ticksPerDay refines the integration without changing the ecology (see the convergence test, 8.3). Never hand-tune a per-tick constant — tune the per-day rate.

0.3.3Carbon is the currency — one unit for energy, biomass and gas

Older drafts used energy and biomass as separate, unitless quantities. That is an unresolvable ambiguity (energy in joules? sugar in grams?) and it made the CO₂ → plant → litter → CO₂ loop unauditable. We fix it by denominating everything in carbon:

  • Photosynthesis removes CO₂ from the cell's air and adds P kg C to the plant's NSC pool E.
  • Growth converts E → structural B with efficiency η; the lost fraction (1−η) is growth respiration, returned to the air as CO₂.
  • Maintenance respiration burns M kg C of E (or of B under starvation) → CO₂.
  • Death moves B → organicCarbon; decomposition returns it to CO₂.

So "energy budget" and "carbon budget" are the same budget, and carbon obeys a conservation law exactly like the nutrients do (4C). One mole of CO₂ carries 12.011 g C; convert at the air-column boundary only.

0.3.4Dimensionless power laws (a correctness rule)

Never write B^q with B in kg C — a fractional exponent on a dimensional quantity produces meaningless units (kg C^0.75 is not a physical unit). Always normalize against a species reference value first:

M = m · B_ref · (B / B_ref)^q  +  t · h_ref · (h / h_ref)      [kg C day⁻¹]
h = h_ref · (B / B_ref)^p_h                                     [m]

Now every exponent acts on a pure ratio, m is cleanly a rate (day⁻¹), and the allometric prefactors a_h, a_c, a_d of 4I.2 are just h_ref / B_ref^p_h etc. All power laws in 4I are to be read in this normalized form.

1ASpatial model — the 3D coordinate framework (length × width × height)

Everything lives in a metric 3D world, so every point, line, and volume must be addressable. The trick that keeps it cheap: continuous geometry for rendering & collision, a coarse voxel grid for the physics. Positions and shapes are stored as real vectors/segments (a leaning trunk, a fallen-log line), then rasterized onto a small stack of voxels the simulation actually steps. This is the 4G/4H "2.5D" layered model given explicit coordinates — the growth equations don't change; they output dimensions that place each organism into this space.

Reference-implementation status. The horizontal grid below is real and now coupled on every axis: the reference world lays its cells out on a rectangular cols × rows grid (each cell carries its grid indices and world-metre centre), and cells exchange seeds (seedSpread, 4W), light (edgeShade — a tall crown shades its neighbour, §B2), water (downhill routing over grid edges, 2.7) and animals (2D foraging movement, natal dispersal, open-boundary immigration and per-edge dispersal barriers, 4Q.4). The default single-row layout reduces the grid to the earlier linear cell chain, so every pre-grid scenario is unchanged.

The vertical axis is real for the soil: with nSoilLayers > 1 a cell is a stack of soil voxels, and both water (2.3) and nutrients (4H.2) are apportioned per layer against each plant's rootDepth profile, so rooting depth is a genuine niche axis. nSoilLayers = 1 (the default) collapses the stack to the historical single well-mixed pool. The root system is complete, including the lateral footprint, dynamic foraging and the 4H.3 archetypes.

Above ground the air column is deliberately NOT voxelised, and this is a considered deviation rather than a gap. Discrete air voxels reintroduce the very bug 4G exists to fix: if every plant in a layer receives that layer's light, competition is symmetric within the layer and nobody is ever suppressed. So the light physics is continuous in height (crowns sorted by height, leaf area accumulated downward) and resolved horizontally by crown-disc overlap at each plant's own (x, z) — strictly more accurate than a voxel stack, since real crowns do not snap to a layer boundary. nStrata survives as the reporting/visualisation discretisation on top. What the vertical light model was missing is fixed separately: shade used to be a pure downward projection, i.e. the sun nailed overhead; sunAngleShade (4G) now displaces each crown's shadow by the real solar geometry.

LOD is deliberately absent and is not a reference-implementation task: it is a host-side rendering concern (the form-vs-function split below — hero trees get geometry, distant trees stay equation state). The reference model is a headless oracle with no renderer, and its per-plant state is already the "distant tree" representation, so there is no detail to switch down. See 9.4.

2.2Light & shading (Beer–Lambert)

LAI(cell)         = ( Σ_p leafArea_p · overlapFrac(p, cell) ) / cellArea     [m² m⁻²]
lightGround(cell) = sunlight · exp(−k · LAI(cell))

The shading term must be a leaf-area index, not a leaf area. k is defined per unit LAI (0.3.2), so the exponent is only dimensionless if we divide the accumulated leaf area by the cell's ground area. (An earlier draft summed raw leaf-area values here; that makes exp() take a quantity in m², which is meaningless and makes the extinction depend on your choice of cellSize.) The sum runs over every plant whose canopy footprint (3.6) overlaps this cell, weighted by the overlapping fraction — so a tall tree shades a wide patch and a sapling only its own cell.

Accumulated once per tick: O(N·f) to write, O(G) to read. In the layered 3D model this becomes a per-stratum LAI stack and the attenuation cascades top-down (4G.1).

2.3Water

evaporation = evapCoeff · max(0, temperature − tempEvapBase) · (water / fieldCapacity)
water += rainfall(season) − evaporation − drainage − Σ uptake(plants)     [mm]

Uptake uses the two-phase apportionment of 3.2.1 (water is a shared cell pool exactly like a nutrient), and the grant lands in the plant's waterReserve. What the plant then does with it is 4J: it is spent on transpiration, the unavoidable cost of opening stomata to let CO₂ in. Water is not consumed by growth — it is traded for carbon, and that trade is the point.

Two transport terms, not one:

  • Below field capacity — water is held in the soil matrix and creeps by capillarity: an isotropic diffusion pass (wet → dry).
  • Above field capacity — water is free and obeys gravity: it runs downhill along the hydraulic-head gradient (2.7), carrying dissolved nutrients with it.

Clamp water ≥ 0. Below wiltingPoint, or when the soil is frozen (2.7), uptake is 0.

2.3aRainfall must be EPISODIC, not a mean

A constant daily drizzle is not a weaker version of real weather — it is a qualitatively different climate, and it silently disables the water submodel. With rain arriving every day the soil sits pinned at field capacity, moistureAvail is 1.0 permanently, stomata never close for want of water, and 4J becomes inert above roughly 2 mm day⁻¹. The V5 productivity-vs-rainfall curve then comes out flat, because there is never a dry spell for water to limit. Drought is an event, not a mean.

rain(t) = 0 most ticks;  a storm of  rainfall · rainInterval  mm  arrives with
          probability  Δt / rainInterval                      // same annual total

Depends on multi-layer soil water. With a single soil bucket, a storm instantly overflows fieldCapacity and drains within a day, so episodic rain delivers less usable water than the same annual total spread evenly — the opposite of the intended effect. Implement the depth layers of 2.3 first, so infiltration can move a storm pulse down the profile where it is protected from evaporation. The reference implementation ships this term defaulted off for exactly this reason.

2.4Gases (the O₂/CO₂ loop)

Each cell's air column gains O₂ / loses CO₂ from photosynthesis, and the reverse from respiration (plants at night + all animals). A diffusion pass mixes neighbors and gently pulls each cell toward a global atmospheric baseline (atmoBaseline*) so the world doesn't drift unbounded. Animals (later phase) read local O₂ as a survival constraint and emit CO₂.

2.5Decomposition & nutrient cycling

On death a plant dumps its structural carbon B into organicCarbon and its actual nutrient content (reserves[i] + tissue[i]) into organicNutrients[i] — so neither carbon nor any nutrient is created or destroyed. Each tick a fraction decomposes, releasing the stored nutrients (not an invented ratio):

frac                = decompRate_eff · Δt        // fraction of the pool turned over this tick
Cmin                = frac · organicCarbon       // [kg C m⁻²] carbon mineralized → CO₂ (0.3.3)
organicCarbon      −= Cmin
cell.co2           += Cmin / (M_C · H)           // → [mol m⁻³];  M_C = 0.012011 kg mol⁻¹
                                                 //   H = air-column height [m] (1A.1)
Nmin_i              = frac · organicNutrients[i] // [g m⁻²] nutrient i released from dead matter
organicNutrients[i]−= Nmin_i
nutrients[i]       += Nmin_i − immobilized_i     // ← see 2.5.1: microbes may TAKE some back

(The co2 line is the one place a per-area pool meets a per-volume field: dividing a kg C m⁻² flux by the molar mass and the column height H yields mol m⁻³. Get this conversion wrong and the carbon balance of 4C will catch you immediately — which is exactly what it is for.) Plus a slow abiotic weathering source per nutrient (bedrock → soil) so long-run soils don't zero out. Closes the cycle: grow → die → decompose → regrow, with both the carbon and the nutrient mass balances of 4C provably conserved.

Decomposition is not a fixed constant — it is performed by decomposers, gated by the soil environment, and limited by the quality of the litter itself (4E):

decompRate_eff = baseDecomp · decomposerActivity · f_moist(water) · f_temp(T) · f_pH(pH) · f_quality(C:N)

so cold, dry, or acidic soils decompose slowly → litter/peat accumulates (realistic tundra & bog behaviour emerges); warm, moist soils turn over fast.

2.5.1Litter quality (C:N) — the control that was missing

Not all dead matter is equal. A nitrogen-rich leaf rots in a season; a nitrogen-poor pine needle or a lignin-rich log takes decades. This single ratio explains most of the variance in real decomposition rates, and without it every biome turns over at the same speed regardless of what died there. Litter quality is already implicit in our state (we track carbon and nutrients in the dead pool separately), so it costs one division:

CN         = organicCarbon · 1000 / organicNutrients[N]        // g C per g N
f_quality  = CN_crit / (CN_crit + CN)          ∈ (0,1]         // low C:N = fast rot

CN_crit ≈ 25 (the classic microbial threshold). Fresh green leaves (C:N ≈ 15) decompose fast; conifer needles (C:N ≈ 60) and wood (C:N ≈ 300–500) decompose slowly — the woodDecompRate ≪ baseDecomp of 4G.5 stops being a magic constant and becomes an emergent consequence of wood's C:N.

Immobilization vs. mineralization (the sign flip). When litter is N-poor (C:N > CN_crit), the decomposers building their own bodies need more N than the litter supplies — so they pull mineral N out of the soil instead of releasing it. The net flux reverses sign:

demand_micro = Cmin · CUE_micro / CN_micro       // N the microbes need (CN_micro ≈ 8)
supply_litter = Nmin_N                            // N the litter released
netN = supply_litter − demand_micro
  netN > 0 →  MINERALIZATION: nutrients[N] += netN            (soil gains N)
  netN < 0 →  IMMOBILIZATION: nutrients[N] += netN (a DRAW)   (soil loses N to microbes,
                                                               capped at what's available)

This is why dumping straw or sawdust on a field makes it temporarily infertile — a real, famous effect that now falls out of the model for free.

Initialise the baseline litter pool BELOW CN_crit (C:N ≈ 15–20), or the V9 validation experiment (12) has no valid control. If the default soil starts at C:N ≈ 30 it is already immobilising, so the sawdust treatment and the control both lock up nitrogen, the difference collapses into the noise, and the test reports that the sign flip does not work when in fact it does. A control must do the opposite of the treatment, not a weaker version of it. (Found this way in ref/.) It also creates a

genuine negative feedback on succession: a conifer stand shedding N-poor needles locks up its own soil N, slows its own growth, and hands an advantage to N-fixers (4E.2). Carbon still goes to CO₂ either way; only the nutrient direction flips.

2.6Soil characteristics — texture, retention & health

Soil is not inert substrate; its physical makeup sets how it holds water and nutrients. Two static-ish per-cell properties (paintable in-editor, 3.5) plus a derived health score:

Texture ∈ [sand … clay] (a fraction or a few fractions sand/silt/clay). Together with organicCarbon it derives water and nutrient holding capacity:

fieldCapacity   = f_wc(clayFraction, organicCarbon)     // mm — max water the cell holds
wiltingPoint    = f_wp(clayFraction)                    // mm — below this, uptake → 0
drainage        = drainRate · max(0, water − fieldCapacity)  // excess water leaves (sink)
CEC_i (retention)= f_cec(clayFraction, organicCarbon)   // 0..1 — cation exchange: holds nutrient i
effLeaching_i   = nutrientDiffusion[i] · (1 − CEC_i)    // clay + humus resist leaching

Consequences that fall out for free: sandy soil drains fast and leaches nutrients (droughty, infertile → desert/pioneer species win); clay/loam with humus retains water and nutrients (fertile → lush growth). Because organicCarbon raises both fieldCapacity and CEC, a thriving ecosystem improves its own soil — a slow positive feedback (soil-building), and its collapse degrades it (desertification). Uptake (3.2) is additionally scaled by a moistureAvail = clamp((water − wiltingPoint)/(fieldCapacity − wiltingPoint), 0, 1) factor so plants can't pull from bone-dry soil.

Soil / biome health is a diagnostic aggregate (0..1), not a driver by default — see 4F. It rolls up fertility, moisture, organic content, and decomposer activity so you can read a cell's or region's condition at a glance.

2.7Topography & hydrology — water runs downhill

Until now water diffused isotropically, which is physically wrong: water is driven by gravity, not by concentration. That one omission erases the single most visible pattern in any real landscape — wet valleys and dry ridges — and with it the moisture gradient that decides where forest, grassland, and bog each sit. It is cheap to fix: add an elevation field and make the flow term follow the hydraulic head instead of the water concentration.

head(cell)   = elevation + water / 1000            [m]      // terrain + water depth
flow(a → b)  = kFlow · max(0, head(a) − head(b)) · Δt       // only ever downhill
water(a) −= Σ_b flow(a→b) ;   water(b) += flow(a→b)         // conservative by construction
  • Runoff only occurs above field capacity (below it, water is held by the matrix and moves by slow capillary diffusion — keep the old isotropic term for that).
  • Dissolved nutrients ride along: a fraction (1 − CEC_i) of nutrient i is carried in the moving water, so hilltops leach and hollows accumulate — valleys become fertile with no scripting. (This is the same leaching term as 2.6, now given a direction.)
  • Cells at a local minimum with no outflow pond → waterlogging → low O₂ in soil → f_moist in 2.5 drops past an optimum (anaerobic) → slow decomposition → peat accumulates. The wetland biome of 4F stops being a hand-set parameter and becomes a consequence of the terrain.
  • Slope also sets erosion (organicCarbon and topsoil creep downhill on steep cells) and modifies the sun angle in 4G.2 (a south-facing slope gets more light — the classic aspect effect that puts different forests on the two sides of one valley).

Freeze gating (needed for the tundra/boreal biomes to be real):

frozen  = T < 0 °C  →  moistureAvail = 0,  uptake = 0,  decompRate_eff ≈ 0
snowPack += precip if T < 0 ;  melts → water when T > 0     (a delayed spring pulse)

Without this, a "tundra" biome would happily let plants drink liquid water at −20 °C. Snowmelt also produces the spring flush that boreal phenology (4N) keys on.

Cost: one extra scalar field and one stencil pass — O(G), no change to 5.

3Multi-nutrient system (the key feature)

Nk independent nutrients, each with its own field layer, dynamics, and — per species — its own demand and response curve. This is what lets "phosphorus drives height" and "species A needs less phosphorus than species B" both be true.

Each nutrient is just an index; adding one = adding a field layer + a column in every species' table. Nothing else in code changes — more variables simply means more to manipulate.

3.1aWhere new nutrients come from — and why nitrogen is different

Every nutrient leaves the system (leaching, drainage, fire, denitrification), so every nutrient needs a source or the world runs down. The sources are not interchangeable:

NutrientSourceMechanism
P, K, Ca, Mg, Fe, …rockmineral weathering (3A.4), released by acids and water
Nthe airbiological fixation + atmospheric deposition

Nitrogen has essentially no geological source. Rock contains almost none; the entire terrestrial N pool ultimately comes from N₂ in the atmosphere, via N-fixers (4E.2) and deposition. So a weathering term alone — however carefully tuned — leaves nitrogen with outflows and no inflow, and every world slowly starves of N no matter how correct the rest of the model is. The decline is slow enough to look like ecological succession rather than a leak, which is what makes it dangerous.

nutrients[N] += (nFixation + nDeposition) · Δt          // g m⁻² — booked against the
                                                        // `fixation` external account (4C)
nutrients[i] += weathering_i · Δt      for i ≠ N        // booked against `bedrock`

Typical nDeposition ≈ 0.5–2 g N m⁻² yr⁻¹ in a temperate landscape (much higher downwind of agriculture — a real and interesting lever for a god game). Both must be booked as flows from a named external reservoir, never as free additions, or the 4C conservation law cannot close. Found by the reference implementation in ref/.

3.2Uptake kinetics (Michaelis–Menten / Monod) + pH

A plant demands nutrient i at a saturating rate limited by root mass and by pH-adjusted availability:

availConc_i = nutrients[i] · pHFactor_i(pH)         // pH locks up some nutrients
demand_i    = Vmax_i · rootMass · availConc_i / (Km_i + availConc_i)
  • Vmax_i — max uptake per unit root. Km_i — half-saturation; low Km_i = efficient scavenger at low concentration (this one parameter encodes "species A thrives on less phosphorus").
  • pHFactor_i(pH) ∈ [0,1] — a per-nutrient bell centered on that nutrient's ideal pH (e.g. P availability collapses at very low/high pH). Makes soil pH a real, tunable lever, not dead data.
  • demand_i is only a request. Actual grants come from 3.2.1 so the shared cell pool is never over-drawn and the result is order-independent.

Downregulation — a full plant stops pulling. The Michaelis–Menten form above saturates on external concentration but has no internal feedback, so a plant keeps mining a rich cell long after its own reserves are full. In a shared cell that is not a harmless inefficiency: the first plant to arrive banks the entire pool and starves every neighbour, for no benefit to itself. Real roots downregulate transporters as internal concentration rises, so:

cap_i    = reserveTarget · tissueConc_i · B          // g — what "full" means for this plant
sated_i  = clamp(1 − reserves[i]/cap_i, 0, 1)        // [–] 1 = empty, 0 = full
demand_i = Vmax_i · rootMass · availConc_i/(Km_i+availConc_i) · moistureAvail · sated_i

reserveTarget ≈ 0.9 (a plant holds about as much loose nutrient as its structure contains). This term was missing from earlier drafts and was found by the reference implementation in ref/ — without it, competition for nutrients is decided by arrival order rather than by uptake kinetics, which quietly defeats the whole point of per-species Vmax/Km.

3.2.1Two-phase resource apportionment (determinism + no over-draw)

Multiple plants share one cell pool. Processing them one-by-one makes the outcome depend on iteration order and — if batched/parallel — lets two plants both take the "full" pool and drive concentration negative. So resource draw is a strict two-phase, order-independent operation, run per cell per resource (every nutrient, plus water):

Phase 1 — GATHER:   each plant computes demand_i (read-only on the cell)
                    totalDemand = Σ demand_i  over plants sharing the cell
Phase 2 — APPORTION: scarcity = min(1, available / totalDemand)
                    each plant receives  grant_i = demand_i · scarcity
                    cell.nutrients[i] -= Σ grant_i     // exactly ≤ available

Properties: order-independent (sum then divide), parallel-safe (Phase 1 is pure reads; Phase 2 is a proportional split), conservative (can never draw more than exists → no negatives), and deterministic (no dependence on agent ordering). This is the correctness backbone that makes fast-forward (4A) and Mass-Entity batching (5) safe. Nutrient grants land in reserves[i], the water grant in waterReserve.

3.3Growth limitation — Liebig's Law of the Minimum

Growth is capped by the scarcest nutrient relative to need. level_i is the plant's internal reserve reserves[i] (filled by uptake in 3.2.1) — not raw soil concentration. Reading reserves decouples a momentary soil dip from growth and models storage (a plant with full reserves survives a lean tick).

r_i           = response_i(reserves[i])       // per species, per nutrient, ∈[0,1]
nutrientFactor = min(r_1, r_2, ..., r_Nk)      // Liebig: the minimum limits

response_i shapes (species chooses per nutrient):

  • Monod (saturating): level / (Kr_i + level) — more is better, diminishing.
  • Optimum (bell): peaks at an optimum, declines if too high (toxicity) — the default for micronutrients.

Default aggregation is Liebig min(). A Multiplicative mode (Π r_i, harsher co-limitation) is available behind limitationMode. Nutrients use Liebig; light/water/CO₂ use a smoother multiplicative co-limitation in 4 — a deliberate split (nutrients are hard-limiting; light/water trade off more continuously).

3.4Nutrient → trait mapping ("phosphorus helps height")

Growth splits into traits height, leaf, root, seed. A per-species influence matrix W[trait][nutrient] sets how strongly each nutrient pushes each trait:

height :  N=0.2  P=0.8  K⁺=0.1     // phosphorus dominates height
leaf   :  N=0.7  P=0.1  K⁺=0.2     // nitrogen dominates leaves (grows leafArea)
root   :  N=0.1  P=0.4  K⁺=0.5
seed   :  N=0.1  P=0.6  B=0.3

Per tick, allocate the net growth budget across traits weighted by W[trait][·] · reserves. P-rich soil → tall trees; N-rich soil → leafy short ones — emergent from the matrix, fully tunable.

3.5Per-grid manipulation (tools / events / gameplay)

Every field is directly read/writable per cell:

GetNutrient(cell,i)   SetNutrient(cell,i,v)   AddNutrient(cell,i,Δ)
AddNutrientRegion(bounds,i,Δ)   SetPH(cell,v)   AddWater(cell,Δ)

Fertilizer, pollution, volcano ash (+P), floods (leach N), editor terrain painting, player farming. Because everything reads the same fields, any manipulation propagates through growth on the next tick — no special-casing.

3.6Footprint — canopy vs. root (two separate extents)

A plant interacts with a disc of cells, not just its own — otherwise a mature tree and a sapling one cell apart wouldn't compete, yet the tree's shade already crosses cells. In the 2D prototype a single footprintRadius serves both. In the 3D model (4G/4H) the two extents diverge and are tracked separately:

  • Canopy footprint (f cells) — aboveground, drives shading (2.2, 4G), set by crown size and phototropic leanVector.
  • Root footprint (V = cells × depth voxels) — belowground, drives uptake (3.2.1, 4H), set by rootType and dynamic foraging.

A shallow-rooted tree can have a wide canopy but narrow roots, or vice-versa — the mismatch is ecologically meaningful. Each adds its own bounded constant factor to per-agent cost (5).

3.7Optimal allocation — plants invest where they hurt (functional balance)

The W matrix (3.4) is static: it says "this species always puts 80 % of its phosphorus into height." But real plants are adaptive allocators — the defining behaviour of a plant is that it grows toward whatever is limiting it. A plant in deep shade builds shoots (chasing light) at the expense of roots; a plant on poor soil builds roots (chasing nutrients) at the expense of shoots. Without this, a shaded plant in our model keeps stubbornly thickening its trunk while it starves, and the whole model loses the most basic thing a plant does.

This is functional-balance / optimal-partitioning theory (Thornley), and it is one line: compare how limiting the aboveground resource is versus the belowground one, and skew the split accordingly.

limit_shoot = g_light(L[crownLayer])          ∈[0,1]   // how satisfied for light
limit_root  = min( φ_nutrient , moistureAvail ) ∈[0,1] // how satisfied for soil resources

shootShare  = limit_root  / (limit_shoot + limit_root + ε)     // ← note the SWAP:
rootShare   = limit_shoot / (limit_shoot + limit_root + ε)     //   invest in the SCARCE one

Read the swap carefully — it is the whole idea. If light is scarce (limit_shoot → 0) then shootShare → 1: build leaves. If the soil is scarce (limit_root → 0) then rootShare → 1: build roots. A plant equally limited by both splits 50/50. The result is smoothly self-correcting: investing in the scarce resource relieves the scarcity, which lowers the incentive — a negative feedback that drives the plant toward the balance point where both resources limit it equally. That equilibrium is precisely what optimality theory predicts real plants sit at.

The species keeps control through a plasticity knob and its W matrix, which now shapes how a share is spent rather than dictating the share itself:

allocFrac[shoot] = lerp( W_static[shoot], shootShare, plasticity )   // plasticity=0 → old behaviour
ΔB_τ             = ΔB · allocFrac[τ] · (W[τ]·reserves)/Σ(W·reserves)

plasticity = 0 reproduces the original static model exactly (so nothing already built breaks); plasticity = 1 is a fully opportunistic plant. This one parameter is a real ecological strategy axis: conservative, fixed-form conifers get a low value; fast, opportunistic pioneers and vines get a high one. Seed allocation stays gated on life stage (only Adult/Mature divert to seeds), and root growth remains subject to the penetration test of 4I.1.

Emergent payoffs: etiolation (shaded seedlings shoot up leggy and thin, exactly as real ones do), high root:shoot ratios in deserts and poor soils, low ones in fertile shade — none of it scripted.

3ASubstances & balanced chemistry — the matter engine

Everything so far tracks carbon and Nk nutrient elements as bare pools. That is enough to grow a forest, but it cannot answer the question a player of a world-tending game will ask constantly: "where did that atom actually go?" When a deer dies, its nitrogen does not teleport into "soil N" — it passes through urea → ammonia → nitrite → nitrate, and each of those is a distinct substance with its own mobility, toxicity, and gaseous escape route. When a shell dissolves, it makes carbonate. When basalt weathers, it consumes CO₂ and makes clay and silica. These transformations are the content.

So we generalize one level: the world tracks substances, and every process is a balanced chemical reaction. This costs surprisingly little, and it buys three things at once: visible, explicable matter cycles; conservation for free; and — because a reaction is just data — an unbounded content surface for creators (4E).

3A.1The substance registry

struct Substance {
    string  name;                  // "nitrate", "calcite", "methane"
    string  formula;               // "NO3-", "CaCO3", "CH4"
    int     elements[Ne];          // atom count per element — THE source of truth (C,H,O,N,P,K,S,Ca,Si,Fe…)
    float   molarMass;             // g mol⁻¹ — DERIVED from `elements`, never hand-entered
    Phase   phase;                 // Gas | Solute | Solid | Biomass
    float   mobility;              // diffusion/leaching rate (gas ≫ solute ≫ solid = 0)
    float   bioAvailable[Nk];      // which plant nutrients this substance can supply, and how readily
    float   toxicity;              // e.g. ammonia, H₂S, heavy metals
}

Key move: a substance's identity is its element vector. Molar mass and every conservation check are derived from it, so a designer cannot author a substance that silently violates physics.

The Nk "nutrients" of 3 do not disappear — they become a view. Soil nitrogen is no longer one pool; it is NH₄⁺ + NO₃⁻ + organic-N, and a plant's uptake (3.2) draws on whichever forms it can use (bioAvailable). That is why one plant thrives on ammonium and another on nitrate, and it is a real, observable distinction between conifers and grasses.

3A.2A reaction, and the rule that makes the world honest

struct Reaction {
    map<Substance,float> reactants;    // stoichiometric coefficients
    map<Substance,float> products;
    RateLaw              rate;         // Monod / mass-action / enzyme-limited
    Agent                catalyst;     // plant | decomposer pool | animal | abiotic
    Conditions           gate;         // needs O₂? anoxic? pH range? T range? light?
    float                energyYield;  // kJ mol⁻¹ — drives WHO does it (3A.5)
}

⚠ The load-time balance check (non-negotiable)

Every reaction is verified at load: Σ reactants.elements == Σ products.elements, for every element, plus charge balance. An unbalanced reaction is a load error, not a runtime warning — the world refuses to start.

This single rule is worth more than any amount of runtime debugging. It means a creator cannot author a reaction that creates or destroys matter, which means the mass conservation law of 4C holds by construction rather than by vigilance. The 4C assert stops being a bug-hunt and becomes a proof.

Conservation is now stated per element, subsuming the carbon and nutrient laws of 4C:

for each element e:   Σ over ALL pools (substances × their elements[e])  =  constant
                      ± (volcanic/weathering influx − burial/escape-to-space)

Six pools become one rule.

3A.4The geosphere — closing the very long loop

Add to SoilCell a small set of mineral pools and run them on a slow geological tick:

struct GeoLayer {                      // beneath the soil column (1A.1)
    float minerals[Nm];                // silicate, carbonate, quartz/SiO₂, ironOxide, apatite(P), clay
    float sediment;                    // eroded material accumulating in hollows (2.7)
    float lithified;                   // sediment turned to rock
    float depthToBedrock;
}
  • Weathering (already a nutrientWeathering term in 2) is now the real reaction: it consumes CO₂ and mineral, and produces solutes and clay. It slows as the mineral is used up — so an old, deeply-weathered landscape becomes genuinely infertile (this is what tropical soils actually are), and only new rock can save it.
  • Erosion → sediment → burial → lithification takes matter out of circulation.
  • Volcanism / uplift puts it back. A volcanic eruption is a 4L disturbance that kills everything nearby and then makes the richest soil on the planet — one of the great ecological ironies, and it will be one of the great moments in a god game.
  • Timescale separation keeps it free: the geo tick runs once per simulated year (or century), not every tick. Cost O(G · Nm) amortized to ≈ 0.

Why this closes the world: without a geosphere, a closed ecosystem slowly buries its phosphorus in sediment and dies, permanently. Real Earth is saved by tectonics. A player tending a world across deep time must have this loop, or their world has an unwinnable slow death built in.

3A.5Who runs which reaction — and why the world self-organizes

Do not assign reactions to organisms by hand. Let thermodynamics do it: each reaction carries an energyYield, and microbes preferentially run the most energetic reaction whose oxidant is available. As oxygen runs out in a waterlogged soil, the community walks down the ladder on its own:

O₂  >  NO₃⁻  >  Mn⁴⁺  >  Fe³⁺  >  SO₄²⁻  >  CO₂        (decreasing energy yield)
 │       │                          │          └→ methanogenesis  (CH₄ — a bog)
 │       │                          └→ sulfate reduction (H₂S — the rotten-egg smell of a marsh)
 │       └→ denitrification (N₂ ↑ — the soil loses its nitrogen)
 └→ aerobic respiration (CO₂ — a healthy soil)

This "redox ladder" is one of the most satisfying emergent structures in all of ecology, and it is nearly free: sort the reactions by energyYield, run them greedily against whatever oxidant remains. Flood a cell, and it will descend the ladder by itself — first losing its nitrogen, then smelling of sulfur, then producing methane. A player who drains it will watch the whole sequence run backwards.

4Per-agent update (one tick) — two-phase order

Because of 3.2.1, a tick is three passes over agents, not one interleaved loop:

PASS A (gather):   each plant computes light/water/nutrient demands over its
                   footprint (read-only). Accumulate per-cell totalDemand and
                   LAI (leaf-area index, 2.2).
PASS B (apportion):per cell, split each shared pool by 3.2.1 → water grant into
                   waterReserve, nutrient grants into reserves[i].
PASS C (update):   per plant:
  1. φ = nutrientFactor = min_i response_i(reserves[i])         // Liebig, 3.3
  2. g_s = stomatal conductance from ψ, K⁺, VPD                 // 4J.1 — ONE dial…
  3. P (photosynthesis) = A · leafArea · CO₂-response(g_s·co2) · Π g_j · φ · captureEff
     Tr (transpiration)  = g_s · leafArea · VPD · M_W           // …TWO consequences
     waterReserve −= Tr ;   if ψ_leaf < ψ_crit → cavitation (4J.2)
  4. M (respiration)    = ( m·B_ref·(B/B_ref)^q + t·height·A_l/A_ref ) · Q10^((T−Tref)/10)
  5. net = P − M                                                // all in kg C day⁻¹
  6. net>0: E (NSC) += net·Δt; build ΔB = η·E_spent, allocated across traits by
            3.7 (adaptive share) × 3.4 (W matrix);
            CO₂ out of the cell → into B; O₂ into the cell;
            move reserves[i] → tissue[i] for the biomass built (locked, not lost)
     net<0: draw down E; if E exhausted → stress += deficit
  7. stress decays when healthy; stress > deathStressThreshold · B → stage = Dead (4.1a)
  8. stage transitions by age/GDD/size; Mature + E > seedCost → reproduce
  9. on death: B → cell.organicCarbon; (reserves[i]+tissue[i]) → cell.organicNutrients[i]
            (large plants become a LogDebris across many cells instead — 4G.5)

4.1aMortality thresholds are RELATIVE to biomass

stress accumulates unmet carbon demand in kg C·day, so a threshold stated as an absolute kg C·day is not size-neutral — it is a wildly different tolerance for a seedling than for a canopy tree. A threshold of 40 kg C·day is 120× a 0.35 kg C seedling's entire mass: the seedling can never reach it and is effectively immortal, so a crowded stand accumulates suppressed individuals that shrink forever and never die, and it never self-thins. Therefore:

death  ⟺  stress > deathStressThreshold · B         // [kg C day] / [kg C] = [day]

deathStressThreshold is then honestly a time: how many days of full carbon deficit this species tolerates before dying (≈ 40–80 for a temperate tree). That a large tree endures a bad decade which would kill a seedling in one season is not a special case to script — it is what having reserves means, and it falls out of this one change. Found by the reference implementation in ref/.

The three sub-steps to notice, because they are what earlier drafts got wrong:

  • Step 3 couples carbon and water through one variable. Opening g_s buys CO₂ and spends water. Set g_s = 1, Tr = 0 to recover the simpler, water-free prototype.
  • Step 4 is where growth self-limits (4I.3): the cost term scales with mass while the gain in step 3 scales with leaf surface, so net → 0 as B grows. No cap needed.
  • Step 6 spends carbon, it does not conjure it. E is a real pool; η < 1 means the rest is growth respiration and goes back to the air as CO₂. This is what keeps 4C's carbon balance closed.

Q10 makes respiration rise with temperature (warmer = faster burn); photosynthesis gets an optional temperature bell (too cold and too hot both reduce it). Clamp all field writes ≥ 0.

Reproduction: a mature plant with E > seedCost spawns seedsPerEvent seeds into cells within dispersalRadius (weighted by wind + distance), each carrying an inherited, mutated genome (4B) and a small nutrient dowry from the parent's reserves. A seed germinates when its cue is met and it can penetrate the substrate (4I.1) and it passes establishmentProb (4N — usually it does not); otherwise it waits in the cell's seedBank (4K.4) or expires.

4ATime model — seasons, cycles & fast-forward

The point of the system: plant seeds, then jump to year 100 and see what the world became. That needs two properties baked in from day one:

  1. The sim is a pure state-transition function. state(t+1) = step(state(t)) depends only on current state + config + a seeded RNG stream in the state. No wall-clock, no rendering dependency → fast-forward is possible and deterministic (same seed + setup → same year-100 forest, every run).
  2. Rendering is optional. step() runs headless. Fast-forward = call it in a tight loop, update visuals only on arrival.

4A.1Time hierarchy (four nested loops)

tick   →  atomic sim step (config tickHz, e.g. 2/sec of real play)
day    →  diurnal loop of ticks: a light phase + a dark phase  ← NEW
season →  a run of days sharing a climate profile (temp, rain, daylight length)
cycle  →  a full loop of seasons = one "year"
struct Season { string name; float durationDays;
                float peakSunlight, temperature, rainfall, daylightFraction; }
struct Cycle  { Season seasons[]; }      // year = Σ season.durationDays · ticksPerDay

Day/night (the diurnal loop). Photosynthesis needs light; respiration and decomposition run day and night. So a plant banks energy during the day and spends it through the night — the daily rise-and-fall of stress and growth is emergent, not scripted:

phaseOfDay  = (tick mod ticksPerDay) / ticksPerDay        // 0..1
isDay       = phaseOfDay < season.daylightFraction        // shorter days in winter
dayProgress = isDay ? phaseOfDay / daylightFraction : 0   // 0..1 across the light phase
sunlight    = isDay ? season.peakSunlight · sin(π · dayProgress) : 0   // dawn→noon→dusk arc

sunlight then feeds Beer–Lambert (2.2). At night sunlight = 0 → photosynthesis halts while respiration continues → net energy goes negative until dawn. Nocturnal CO₂ rises and O₂ dips in the gas field automatically (2.4). Species can override the daytime assumption via their metabolism (4E) — e.g. a CAM plant that fixes CO₂ at night. daylightFraction shortening in winter shortens the photosynthetic window, compounding seasonal slowdown.

4A.2How seasons change the plants (the causal chain)

Seasons never touch plants directly — they move the environment fields, and 4 responds automatically:

peakSunlight ↓ or daylightFraction ↓ → lightGround ↓ → photosynthesis ↓
temperature ↑   → respiration ↑ + evaporation ↑ → water stress
rainfall ↓      → water ↓ → uptake ↓, stress ↑

Winter (low light, cold, dry) slows growth, raises stress, sheds leafArea, and triggers dormancy — because the energy budget goes negative — while spring rebounds. Deciduous vs. evergreen, dormancy, seasonal flowering all emerge from species thresholds; add a per-species dormancyTrigger (temp/daylight below X → suspend growth, shed canopy) for explicit leaf-drop.

Latitude (latitude, default 0 = off). The day-length swing was long written as a hardcoded 0.5 + 0.12·sin(2π(doy−80)/365) — and that 0.12 is a latitude (≈41 °N), silently applied to every biome, boreal included. With latitude set, day length comes from the real sunrise equation instead: declination δ = 23.44°·sin(2π(doy−80)/365), sunset hour angle cos ω = −tan(lat)·tan(δ), daylight fraction ω/π — clamped, so beyond the polar circles polar day and polar night emerge rather than being special-cased — and noon PAR scaled by the solar-elevation factor cos(lat − δ), so a high-latitude summer is long but slanted. Validated against published day lengths at 41.5/52/62/68/78 °N. The legacy fixed swing survives as daylenAmp (default 0.12; 0 is a true equatorial constant 12 h day), so latitude = 0 is bit-identical to the pre-latitude model. The four biomes now carry their real latitudes (boreal 62 °N, deciduous 48 °N, conifer 44 °N, mediterranean 40 °N). Assigning them exposed that peakSunlight had been a hand-computed latitude: boreal's was set to 32.0 and commented "high latitude, low sun angle", and 40 × cos(lat − declination) gives 31.3 — so keeping both would double-count the sun angle. Boreal and conifer therefore revert to the overhead default and the geometry does the work, while mediterranean's 48 is deliberately kept, because geometry gives only 38.3 there: that number is atmospheric transmissivity (a cloudless sky), not a sun-angle proxy. A tuned constant is indistinguishable from a real one until something computes what it was standing in for.

Stochastic weather (weatherVar, default 0 = off; weatherMemory, days). Temperature was otherwise a perfect sinusoid — every year an exact replay, so nothing could key off a warm spell or a bad year. weatherVar adds a temperature anomaly drawn as an Ornstein–Uhlenbeck process, advanced by its exact discretisation X ← X·a + σ√(1−a²)·Z, a = exp(−dt/τ). Two properties this buys, both measured: the anomaly is autocorrelated (weather persists for days — independent per-tick noise would average out inside a day and do nothing), and it is timestep-invariant — the realised sd is weatherVar and the correlation time weatherMemory whether the model is integrated 4 or 48 times a day, which a naive per-tick AR(1) would not give. With weatherVar = 0 no random draw is made at all, so the RNG stream is untouched.

Wet and dry years (rainVar, default 0 = off; rainMemory, days). rainInterval gives day-to-day storminess, but a coin per tick averages out over a year — it can make a dry week, never a dry decade. rainVar adds the multi-year signal: the same OU process in log space, exponentiated into a positive multiplier on the rain amount, advanced once per tick in _climate and only read in _fields (which applies it inside a per-cell loop, where advancing it would make the statistics depend on cell count). It is mean-preserving — the multiplier is exp(Y − rainVar²/2), expectation exactly 1 — so enabling it adds variance without quietly reducing total precipitation, which is what makes its effects interpretable. Measured consequence, and a genuinely emergent one: mean-preserving rainfall variability lowers mean productivity by 12–13 % in a water-limited biome (Jensen's inequality on a saturating water response — a drought year costs more than the next wet year returns), while a light/temperature-limited biome barely notices. Note that with a long rainMemory any individual finite run is randomly wetter or drier than nominal, so experiments should report the realised multiplier and use several seeds.

4A.3Fast-forward to the future

void Advance(int cycles) {                 // Advance(100) → +100 years
    long target = now + cycles · ticksPerCycle;
    renderer.Detach();                      // headless
    while (now < target) step();            // pure sim, as fast as CPU allows
    renderer.Attach(); renderer.Resync();   // rebuild visuals from final state
}
  • step() is O(G·Nk·Nd + N·Nk·V·R) (5) with no rendering, so centuries run in seconds–minutes depending on grid + live-agent count.
  • Use aggregate mode for long jumps: run the world as per-cell population statistics (biomass/pop per species per cell) at O(G), re-instantiate individuals only on arrival. Turns century jumps into cheap grid math.
  • Fidelity caveat: aggregate mode is a faithful approximation, not bit-identical to a fully-detailed run. Determinism is exact within a chosen fidelity mode — a full-detail run reproduces exactly; a full↔aggregate mix does not. State which mode a save was produced in.
  • Snapshot every snapshotEveryCycles (4D) to scrub a timeline (0→25→50→75→100) rather than only landing on the end.

4A.4Locking a cycle (repeat one year forever)

  • Climate loops automatically: seasonIndex = f(tick mod ticksPerCycle), so the same weather returns yearly with no special handling. Default behavior.
  • lockCycle additionally freezes the climate definition at lockedCycleId, cancelling any climateDrift trend, so year 31 = year 30 exactly. The ecosystem still evolves across repeats (plants keep growing, competing, dying) — only the weather pattern repeats. "Fix this one year and let the forest live inside it."
config.lockCycle=true;  config.lockedCycleId=30;  config.climateDrift=0.0;

4A.5Constraints this imposes on the code

  • step() side-effect-free except on world state — no system clock, no per-frame UE calls inside it.
  • RNG is an explicit seeded stream in world state (reproducible + serializable).
  • Render layer subscribes to state, never drives it (attach/detach/resync).
  • Season/cycle are pure config (Data Assets) → creators author custom calendars (2/6/N seasons, alien worlds) without code.

4BIndividual variation, genetics & inheritance

Without variation, every plant of a species is an identical clone — forests look fake and nothing can adapt. Each individual carries a compact genomeSeed from which small multiplicative modifiers on select params (baseGrowthRate, maxHeight, Km[i], drought tolerance) are derived deterministically at germination and cached. Magnitude is controlled by geneticVariance (0 = clones).

  • Inheritance: a seed's genomeSeed derives from the parent's plus a mutation drawn from the world RNG stream (rate = mutationRate, blend = heritability).
  • Selection is emergent: over the century-scale jumps (4A.3), variants whose modifiers suit the local soil/climate out-reproduce the rest — so "see how the environment changed" becomes "see how the population adapted." This is a large payoff for a tiny amount of state (4 bytes/agent).
  • Determinism preserved because all randomness flows from the seeded state RNG; derived modifiers are a pure function of genomeSeed.

4CNumerical stability & safety

Fixed-timestep field math needs guardrails or it silently corrupts long runs:

  • Non-negativity: clamp every field ≥ 0 after each sink. Over-draw is already impossible for shared pools via 3.2.1; clamp the rest (evaporation, decay).
  • Diffusion stability (CFL-like): an explicit diffusion pass is stable only if diffusionRate · neighborCount < 0.5. Cap configured rates to this, or sub-step the diffusion, otherwise the grid oscillates and diverges.
  • Rates are per-tick: all coefficients are defined per tick. If tickHz changes, scale rates accordingly or behavior shifts — document per scenario.
  • NaN/denormal guards: clamp inputs to exp() and Michaelis–Menten denominators (Km_i + conc > 0).
  • Conservation checks (debug builds). Two independent invariants, asserted every tick. They are the cheapest bug-detector in the whole project: almost every modelling error you can make shows up as a violation of one of them.

Superseded by 3A.2 once substances are enabled. With balanced reactions, both checks below collapse into one law stated per chemical element, and it holds by construction because an unbalanced reaction cannot even load. Keep the two checks below for the pre-chemistry prototype (3A.6 adoption path, Ns = Nk, no reactions).

(1) Nutrients — for each nutrient i, total mass over all six pools `` Σ_cells nutrients[i] + Σ_plants(reserves[i] + tissue[i]) + Σ_cells organicNutrients[i] + Σ_logs woodNutrients[i] + Σ_cells (seedBank[s] · seedDowry[s][i]) ` (A dormant seed is a real, if tiny, nutrient pool — seedDowry[s][i] is what the parent packed into it. Six pools, not four.) must change only by (weathering + Nfixation + fertilizer) − (leaching + drainage export + fire volatilization)`. Reproduction, death, decomposition, resorption and mycorrhizal transfer only ever move nutrients between pools — they must net to zero. (A seed carries a small nutrient dowry from its parent's reserves — count it, don't create it.)

(2) Carbon — the loop that the earlier draft never audited (0.3.3): `` Σ_plants(B + E) + Σ_cells organicCarbon + Σ_logs woodMass + Σ_cells decomposerBiomass + Σ_cells (co2 · airVolume · 12.011e−3) ` must change only by photosynthetic fixation − (respiration + growth respiration + decomposition + combustion) ± atmospheric exchange with the baseline`. If carbon is not conserved, either a growth path is creating biomass from nothing or a death path is deleting it — and the fast-forward feature will amplify that error over a century into a completely fictitious world. This assert is what makes a 100-year jump trustworthy.

Log the drift each tick; a well-formed model holds both to floating-point noise (relative error < 1e−6 per tick). A steadily growing drift is a real bug, not rounding.

4DState serialization, save/load & snapshots

World state = field SoA arrays + agent array + RNG state + clock (tick/cycle) + config reference. Serializing all of it is a save; because 4A is deterministic, a reloaded save stepped forward reproduces the same future.

  • Format: versioned header + raw dump of the SoA float arrays + packed agent records; optional compression. Fast because it's already flat arrays.
  • Snapshots (4A.3 timeline scrub) are just periodic serializations held in a ring buffer bounded by memory; snapshotEveryCycles trades memory for scrub granularity.
  • Aggregate saves must record their fidelity mode (4A.3) so a reload knows it holds statistics, not individuals.

4EModular metabolism — every organism exchanges differently

Not everything photosynthesizes. Plants fix carbon and release O₂; fungi and soil microbes decompose (consume O₂, release CO₂, mineralize nutrients); animals respire and graze; legume symbionts fix nitrogen from air. Rather than hard-code "plants make O₂," an organism's chemistry is a data-driven list of metabolic reactions — the single most important thing for making the framework modifiable and transferable.

4E.1The reaction primitive

struct MetabolicReaction {
    map<Resource,float> inputs;    // consumed per unit rate: light, CO2, O2, water,
                                   //   nutrient[i], organicCarbon, preyBiomass
    map<Resource,float> outputs;   // produced: O2, CO2, biomass, mineralized nutrient[i], waste
    RateFn              rate;      // how fast, given local fields & organism state
    bool                dayOnly;   // gate on isDay (4A.1) — light reactions
}
struct MetabolicProfile { MetabolicReaction reactions[]; }   // an organism IS its reactions

Each tick, for each organism, every reaction computes its rate (bounded by the scarcest input via the same two-phase apportionment as 3.2.1 so shared fields — gases, organic matter — are never over-drawn), then applies stoichiometry: inputs leave their fields, outputs enter theirs, energy/biomass update the organism. Gas balance, nutrient mineralization, and the O₂/CO₂ loop all become emergent sums over whatever reactions the world's organisms happen to run.

4E.3Decomposers: field vs. agent

Microbial decomposers are too numerous to be agents — model them as the per-cell scalar decomposerBiomass (a Saprotroph reaction operating on the cell), which grows when there's organic matter + warmth + moisture and starves otherwise. This makes decomposerActivity in 2.5 emergent and biome-dependent. Macro-fungi and detritivores (mushrooms, worms) can be real agents if you want visible mycelial spread or gameplay — same MetabolicProfile, just instanced. Cold/dry/ acidic cells → low decomposerBiomass → slow turnover → litter builds up.

4E.4Complexity note

Adds O(N · R) to the agent update where R = reactions per organism (a small constant, usually 1–3). Shared-field reactions reuse the 3.2.1 apportion pass, so no new complexity class — still linear (5).

4FBiomes — bundling a world, and reading its health

A biome is not new machinery; it is a preset bundle of the parameters above, so the same engine produces rainforest, desert, tundra, wetland, or an alien world by data alone.

4F.1What a biome bundles (Data Asset)

struct Biome {
    Cycle            climate;         // seasons + day-length + rainfall/temperature
    SoilProfile      soil;           // clayFraction map, initial nutrients[Nk], pH
    Species[]        flora;           // the species pool allowed to colonize
    MetabolicProfile decomposers;    // the saprotroph/detritivore community + rates
    Species[]        fauna;          // animals (later phase)
    float            healthWeights[];// how 4F.2 weighs its health readout
}

Presets differ only in these values: tropical rainforest (warm, wet, long days, fast decomposition, N-rich, dense canopy pool) vs. boreal/tundra (cold, short days, near-frozen decomposition → peat, acidic, slow conifers) vs. desert (hot, dry, sandy/low-CEC, sparse CAM flora) vs. wetland (waterlogged → anaerobic, slow decomposition, specialized flora). Blend biomes across the map for gradients/ecotones by lerping the field initial conditions.

The flora pool must be coherent — species that actually co-occur in the region the biome represents. This looks like a curation detail and is really a correctness one: the biome decides what is present to compete, and the winner is supposed to emerge (9.3). Stock it with species from two different continents that never meet in nature and the "prediction" is an artifact of a matchup that does not exist, which can surface as a climax that flips unpredictably with the random seed. When that happens the fix is to make the pool coherent, not to tune the mechanism that exposed it (4L.1).

4F.2Biome health (diagnostic metric)

A 0..1 rollup that lets you see ecosystem condition and drives the metrics time-series (6.4):

biomeHealth = w_bio·biodiversity            // species evenness (Shannon index)
            + w_bm ·(biomass / biomassPotential)
            + w_soil·soilFertility          // mean available nutrients vs. target
            + w_bal·nutrientBalance         // how close to Liebig-balanced (no single limiter)
            + w_dec·decomposerActivity      // a living soil food web
            + w_str·(1 − meanStressFraction)

By default it's observation only (6.4). Optionally enable a gentle feedback (healthFeedback) where very low health slows recovery (degraded soil resists regrowth) — powerful for gameplay, off by default to keep dynamics transparent.

4GAboveground 3D — light strata, shade, phototropism, obstacles, deadfall

The 2D model gives each cell one ground-light value. Real forests are vertical: a tall tree grabs light at the top, the understory lives on leftovers, shadows fall sideways as the sun moves, saplings bend into gaps, rocks block roots, and dead trees crash across their neighbours. We add all of this with a cheap "2.5D" layered-column model (like SORTIE/gap forest models) — a small stack of height strata per cell, not full voxels — so cost stays linear.

"Shadows fall sideways as the sun moves" is implemented (sunAngleShade, default 0 = off). Shade was long computed as a straight-down projection of each crown, which quietly assumes an overhead sun — true only at the equator at noon, and plainly wrong once a latitude is set (4A.2). With it on, the noon solar elevation 90° − |lat − declination| gives a shadow reach of height / tan(elevation) and each crown's shade disc is displaced that far away from the sun, i.e. poleward, in both the in-cell and cross-cell (edgeShade) paths. Light competition therefore becomes directional: a tree suppresses its poleward neighbours and barely touches those equatorward. Measured at 62 °N, a 13 m tree throws its shade 10.5 m (0.80 × height) in midsummer and 1.9 × height at the equinox — the reach lengthens through the year on its own, because declination is recomputed each refresh. Damped by the parameter to represent diffuse skylight (which has no direction) and capped at 5 × height so a near-horizon sun cannot throw an unbounded shadow.

4G.0This section is load-bearing — it is not a fidelity upgrade

If every plant in a cell reads the same lightGround, light competition is SYMMETRIC, and four validation targets become simultaneously unreachable. Sixty identical seedlings each take 1/60th of the light, grow at identical rates, and plateau together forever. No individual is ever suppressed, so none dies, so:

TargetWhy it cannot happen
V1 self-thinningnothing ever dies of suppression
V2 successionpioneers are never overtopped, so they never drop out
V3 coexistenceno light niche exists to partition
V4 intermediate disturbancethere is no suppressed cohort for a gap to release

No parameter value rescues any of them, because the missing thing is not a quantity — it is the one-sidedness of the interaction. Light must be intercepted top-down, tallest crown first. This was confirmed by direct experiment in the reference implementation (ref/): with symmetric light a 60-plant stand held all 60 individuals indefinitely; with top-down interception the same stand produced emergent dominants and a 30× size spread.

A second trap, once you implement strata. Discrete layers alone are not sufficient: if every plant in a layer receives that layer's light, competition is symmetric again within the layer — and early in a run every plant is in layer 0, so you land back on the original bug with more code. Keep the attenuation continuous in height (sort crowns by height, accumulate leaf area downward) and treat the strata as the reporting and rendering discretisation on top of it. That is also the more accurate of the two: real crowns do not snap to a layer boundary.

4G.1Height strata & vertical light attenuation

The air column is split into La height layers (config; e.g. floor 0–2 m, shrub 2–8 m, sub-canopy 8–20 m, canopy 20 m+). A plant's crown sits in the stratum matching its height (crownLayer); its leaf area is deposited there. Light attenuates top-down through the layers (Beer–Lambert per layer):

L[top]      = sunlight
L[layer d]  = L[layer d+1] · exp(−k · LAI[layers above d])
captured    = L[crownLayer] · leafArea · captureEff        // leafArea, NOT crownArea (4I.2a)

So a canopy tree grabs full sun; a medium tree it overtops receives only L[sub-canopy] → it dies or only shade-tolerant species (low lightTolerance) persist beneath. Vertical stratification and succession are now explicit. captureEff (per species/stage) is "how efficiently a tree uses the light it gets," and it can differ by strata (a shade species is efficient in dim light). This is a per-cell La-vector, not per-plant-pair — still O(N·f + G·La).

4G.2Directional shade (the sun moves, shadows fall sideways)

The sun has an azimuth + elevation that sweep with the day/night cycle (4A), so a tall plant shades cells down-sun of it, not its own column:

shadowLen   = height / tan(sunElevation)     // long at dawn/dusk, short at noon
shadowCells = line of cells from base along −sunAzimuth, of length shadowLen

Each shadowed cell gets this plant's crown leaf-area splatted into its upper strata (darkening the top of the neighbour's column). We do not ray-trace per plant — we splat a short down-sun line (a small bounded kernel) into a per-cell shadeField, O(N·shadowCells). Cheaper option: a day-integrated shadow (sum a few sun positions once per day) for smoother, static-per-day shade.

4G.3Phototropism — bending toward light

Each plant's leanVector drifts toward the local light gradient: it samples L[crownLayer] in neighbouring columns and grows its crown offset toward the brightest (a canopy gap). Crowns lean into gaps (realistic), shifting which cells they capture from and shade — a real competitive edge for a plant beside a gap. Cheap: one gradient over the canopy footprint per tick.

4G.3aStatus — the crown leans; the payoff is a step, not a slope

Built as Plant.lean_x/lean_z, the crown centre's displacement from the stem. On the monthly shade cadence each plant samples optical depth one crown radius out in each cardinal direction — counting only taller crowns, as shade_load does — and steps up the gradient at phototropism crown-radii per year, capped at leanMax crown radii. The leaned centre is what casts shade and what receives light. The stem never moves: a tree cannot walk to the light, only put new growth on the lit side, and keeping the trunk fixed also matters mechanically, since roots, seed placement and the conspecific-density census all key on it. phototropism = 0 leaves the lean at exactly 0.0, so golden stays 10/10.

The benefit is all-or-nothing, because 4G.1's shading is a binary disc test (dx² + dz² ≤ r², with no partial overlap). Leaning therefore cannot buy a partial escape — it pays only by carrying the crown entirely clear. Staged geometry, 25 yr: at leanMax 0.0–0.8 the focal tree stays under its neighbour's disc, holds shade_load 2.28, receives no light and dies; at leanMax 1.0 it clears the disc, shade_load falls to 0.00, light to 14.51, and it reaches 199.7 kg C. Life or death with nothing between.

At stand scale this does not aggregate. Over two seeds, biomass and stem count disagree in sign (+5.8 %/−4.3 %, −9 %/+5.5 %), so the individual advantage is a null at stand level. The one quantity moving the same way on both seeds is LAI, +11.5 % and +6.9 % — crowns that can move sideways pack the canopy more completely, which is the effect leaning should have and the only one the data supports. At the default leanMax = 0.5 the mechanism is very nearly inert (−0.4 % biomass), exactly as the escape threshold predicts.

Open follow-on: making the individual edge aggregate would need graded shade — partial disc overlap producing partial shading — which is a change to B2's core light model that would break the golden oracle and move every result in the project. Recorded as a deliberate decision, not taken here.

4G.4Obstacles — rocks & surface cover

SoilCell.rockFraction ∈ [0,1] (paintable, 3.5):

  • Rooting volume, water/nutrient capacity, and germination sites all scale with exposed soil (1 − rockFraction) — less soil, fewer establishment spots.
  • Only species whose substrateTolerance allows (lithophytes, shallow specialists) establish where rock is high; a big canopy tree can't root on bare rock, but a hardy shrub or a sapling in a soil pocket can. Rocky outcrops grow a distinct sparse community — emergent, not scripted.
  • Optional: a boulder also casts a small shadow and retains moisture at its base.

4G.4aStatus — rock as an absence, not a pool

Implemented as SoilCell.rock ∈ [0,1], set for every cell from rockFraction and paintable per-cell on top (3.5). It is deliberately not a matter pool: rock is the absence of soil, so it never touches the ledger. What it does is shrink what the soil that is there can do. rockFraction = 0 makes every term below multiply by exactly 1.0 ⇒ golden 10/10. The optional boulder shadow is not built.

One multiplier covers both of this section's bullets. A propagule lands on soil with probability 1 − rock, where anything grows, or on rock, where only a species that tolerates rock can hold: substrate_ok = (1 − rock) + rock·rockTolerance. "Fewer establishment spots for everyone" and "only lithophytes get the rest" are the same fact seen from two ends, so they need no separate machinery. It is applied to both recruitment routes — direct germination and advance-regeneration release — since filtering only one would leave rock bypassable by the other.

Water and exchange capacity scale with the soil fraction — but that alone does NOT make rocky ground droughty, and measuring it is what showed why. On the default climate moisture_avail read 1.0000 at every rock level (the cell sits at field capacity all year; a smaller bucket that is always full is not dry), and on a water-limited run it went the wrong way, 0.454 → 0.623 as rock rose, because moisture is a ratio against capacity and a smaller store fed by continuous rain sits full more of the time. Real drought on skeletal soil comes from the interval between rains outlasting what the small store can bridge. With the same total rainfall delivered every 20 days instead of daily, a 90 %-rock cell goes from habitable to moisture 0.000 and zero stems, while bare soil under the identical regime still carries a sparse stand. Rock is not droughty; rock and rainfall episodicity are droughty together — an interaction, not a property, and it predicts that an outcrop community is governed by rainfall variability far more than by mean rainfall.

The lithophyte filter needed the ROOTING-VOLUME bullet to bite, and with it the outcrop community appears. Gating establishment alone was not enough: an intolerant tree that got in then grew as though the rock were not there, and still held ~36 % of the biomass at 90 % rock. An outcrop is not sparser, it is differently composed. Stated limits. Rock scales soil volume, not the nutrient stock — those grams sit more concentrated in the remaining soil rather than disappearing. Scaling them would have to happen at initialisation, and would then behave differently depending on whether the rock came from the parameter or was painted later by a host; that dual path is a stale-state bug waiting to happen, so nutrient stocks stay a scenario input. (The field_capacity memo key does carry the rock fraction, for that reason — a memo key that omits a field its value depends on is a bug waiting for a caller that does not exist yet, and 6.5 ships exactly that caller.) Assigning real rockTolerance values to the shipped flora is an open calibration decision, like the root archetypes of 4H.3.

4G.5Deadfall — when a tree falls (logs / coarse woody debris)

A plant above deadfallSizeThreshold doesn't just dump into its own cell on death — it becomes a LogDebris lying across a swath of cells:

struct LogDebris {
    uint32 cells[];            // line of cells, stump → crown-tip (length = height)
    float  woodMass;           // large, slow-decomposing pool
    float  woodNutrients[Nk];  // nutrients locked in the trunk (conserves mass, 4C)
    bool   suspended;          // caught between tall neighbours vs. flat on ground
    float  decompState;        // 0..1
}
  • Fall direction: toward the biggest canopy gap / the way it leaned (leanVector) / away from densest neighbours, plus randomness.
  • Suspended vs. grounded: if it lands against ≥2 tall neighbours it is suspended — a raised trunk that shades the cells beneath (adds to shadeField) without smothering their soil, so understory there gets low light but seedbeds survive. Grounded, it lies on the soil surface.
  • Crush on impact: small plants/saplings in covered cells die with probability ∝ woodMass / plantSize — a log flattens seedlings, not mature trees; and germination on covered soil is blocked while the log lies there.
  • Nurse log (the payoff): a grounded log decomposes slowly (coarse wood ≫ leaf litter; needs wood-decay fungi, 4E) at woodDecompRate, releasing woodNutrients into the covered cells over years → surviving neighbours grow better and the log becomes a prime germination substrate (raised, moist, nutrient-rich): seedlings with high nurseLogAffinity preferentially establish along it. This reproduces real nurse-log succession — death directly seeding new life. Routes through the normal decomposer system (2.5/4E), conserving mass.

4G.5aStatus — built, and the headline claim is the wrong one

Implemented as a per-cell coarse-debris pool (soil.cwd) rather than a LogDebris object: coarseC, coarseNut and coarse_age, the mass-weighted decay progress of the wood in that cell. Everything above is present — the fall toward the biggest gap, the spread across as many cells as the tree was tall, crush on impact, slow fragmentation into ordinary litter, and the nurse-log effect on the seedbed. Off by default (deadfallSize = 0) and bit-identical to the golden oracle. suspended is the one bullet not built: it needs a per-log object to be meaningful, and its effect (shade without smothering) is a small correction to the two ends already modelled.

Crush needed two corrections, both forced by measurement. "Probability ∝ woodMass / plantSize", implemented literally as min(1, woodC/plantB), was not size-selective at all over 200 replicate falls — every class from 0.3 to 100 kg C died at ~60 %, because the clamp binds for anything lighter than the log, and the claim this section makes lived entirely inside the region the clamp had flattened. Worse, the crush applied to every plant sharing the cell, which silently asserts that a falling tree covers the whole cell; since a biome plot is one cell of 200 m², each canopy death rolled the dice on the entire stand and flattened it (above-ground carbon 6.53 → 1.06 kg C m⁻²). At 1 m cells the same code would have looked fine — a reminder that a per-cell rule carries an implicit statement about cell size. With the saturating form woodC/(woodC + plantB) and the footprint term (crown area over cell area), 1000 replicate falls give 16.8 ± 1.2 % for a 0.3 kg seedling against 9.5 ± 0.9 % for a 100 kg tree, flat at the ceiling below and falling as the masses converge. A domino then falls out unbidden — a crushed sapling large enough to be a log crushes the next one — and has to be measured separately or it inflates everything.

The nurse log is real and the sign flips, from one state variable: against bare ground, recruitment is −41 % under a fresh trunk and +74 % under a rotted one (four seeds, agreeing individually at every level), with the seedbed genuinely site-limited throughout.

But the "large, slow-decomposing pool" is not where the value is. Measured abiotically — no plants, the same carbon and nitrogen delivered as litter or as a log — the wood releases 5 % more nitrogen over 60 years and peaks eleven years later. That is all. The cause is not the wood: organicC in this model already turns over at k ≈ 0.042 yr⁻¹, essentially the CWD rate, because it is bulk soil organic matter with protected carbon (4Y) rather than a leaf-litter pool, and real leaf litter is ten to twenty times faster. There is nothing for a fast/slow contrast to be a contrast against. Logged for calibration; not compensated by slowing the wood, which would be manufacturing an effect by tuning.

So a log matters here because it is a PLACE, not because it is slow — it lands across cells the tree never occupied, it kills what it lands on with a real size bias, and it turns the ground it covers from hostile to prime as it rots.

At stand scale (temperate_conifer, 150 yr, two seeds) deadfall is a strong disturbance: above-ground carbon falls 41–46 %, LAI and canopy stems fall with it, and NPP does not change — the site produces the same carbon and holds less of it standing, because trees keep being knocked over. Composition shifts toward the shade-tolerant Tsuga on both seeds (15→28 %, 12→39 %). No cause is claimed for that shift: deadfall does three things at once here, and separating them has not been done. deadfallCrush is likewise a plausible default rather than a calibrated one, so the size of the biomass reduction is what that default produces, not a prediction.

4HBelowground 3D — root systems, foraging & competition

Roots are never rendered but fully simulated — they decide who drinks and eats from which soil, and that is where much competition, coexistence, and territory is settled. This is the "hidden algorithm" driving growth.

4H.1Soil depth layers

Soil under each cell is split into Nd depth layers (config; e.g. topsoil / subsoil / deep), each with its own nutrients[Nk] and water:

  • Topsoil (d0): nutrient-rich (decomposition & litter land here), dries fast.
  • Subsoil/deep (d1,d2): stabler water, fewer nutrients — a drought refuge.

Decomposition adds to topsoil; weathering feeds the deepest layer; water infiltrates downward; leaching (2.6) carries nutrients down the stack. (This is where the 2D nutrients[i]/water become per-depth arrays.)

4H.2Root system = a set of soil voxels

A plant's roots occupy a set of (cell, depth) soil voxels (its rootSetId list) — its belowground footprint, separate from the canopy footprint (3.6). The 3.2.1 two-phase apportionment runs per voxel: within each voxel, plants split that voxel's pool in proportion to the root mass each has there. So belowground competition stays local, mass-conservative, and order-independent — the same engine, just per voxel.

Implemented (vertical only). With nSoilLayers > 1 a cell is a stack of soil layers and both water and nutrients are apportioned per layer against each plant's rootDepth profile (root fraction × what that layer holds, then sum-then- divide within the layer), so depth is a genuine niche axis rather than a drought knob. Crucially the vertical profile is not imposed: each flux enters at the depth it physically arrives at — litter mineralisation, deposition and fixation at the top, bedrock weathering at the bottom — and leaching is a cascade, each layer's loss landing in the one below with only the deepest exiting to drainage. From layers started deliberately equal, that alone reproduces the textbook contrast: N ends surface-concentrated (it cycles through litter) while P and K end bottom-concentrated (they come from rock). Measured consequence: rooting depth becomes a repeatable competitive axis — with N limiting and surface-held, a surface mat beats an evenly-spread rooter in every seed, where in a single mixed pool the same pair merely drifts. That is 4H.5's first bullet; its coexistence bullet needs the two strategies limited by different resources at different depths. nSoilLayers = 1 (the default) collapses all of this to the historical single pool.

The lateral half is implemented too. rootLateral (species, default 0) is the fraction of a plant's root mass sitting outside its home cell, spread over the grid neighbours — so rootSetId finally spans (cell, depth) rather than depth alone. Apportionment was generalised from "the plants standing in this cell" to every plant with root mass in it, each pulling in proportion to its share there, so belowground competition stops respecting the cell boundary while staying order-independent and mass-conservative. Measured on a rich cell beside a poor one with plants only on the poor side: at rootLateral = 0 the rich cell is unreachable and its N sits untouched (11.8); at 0.5 the same plants draw it down to 2.7 and convert it into ~9 % more biomass. Demand is footprint-aware as well, so a plant perceives the soil it reaches rather than the ground it stands on.

Foraging is dynamic (rootForage, species, default 0 — 4H.4). On the same slow cadence as the CNDD census, a plant scores its home cell and its neighbours by (scarcest reachable nutrient ÷ its Km) ÷ (1 + root mass already competing there) — Liebig on top because roots chase what is limiting, contest underneath because full soil is worth less than empty soil holding the same nutrients — then relaxes its allocation toward those scores, capped by rootLateral. Deterministic and bounded to home + neighbours, so per-plant cost is constant (4H.4's maxRootVoxels, implicit in the adjacency). Measured against a rich neighbour on one side and a poor one on the other: a static footprint splits its lateral budget blindly 30/30, foraging shifts it to 34/26, mines the rich side harder (soil N 8.58 → 7.25) and spares the poor side (4.08 → 5.21). The shift is modest at equilibrium because foraging erodes the gradient it responds to — cells that start 100× apart end ~1.5× apart, so the cumulative work shows in the asymmetric soils rather than the final allocation.

The 4H.3 archetypes are implemented as a root_type trait mapping each morphology to (depth band, lateral, forage). Depth is a band, not a value: drought tolerance positions a species within its archetype's band, so morphology and the measured drought axis compose instead of overwriting each other. Opt-in — no shipped species carries one yet, so this is bit-identical; assigning archetypes to the real flora is a calibration decision. Measured, 4H.5's coexistence bullet still does not reproduce, and the archetypes explain why: differing in root type made coexistence worse (the taproot was losing on fitness, not partitioning), drought changed nothing because N stayed stripped to ~0 in every layer, and relieving N quadrupled the taproot's share (4 % → 16 %) yet still left it losing — because the top layers are bare while the bottom holds a large P/K reserve. The surface is where the nutrient cycle runs: litter mineralises on top and is re-absorbed, so shallow roots intercept a renewed flux while a taproot sits on a slowly-renewed stock, and in a closed recycling system flux beats stock. Vertical coexistence therefore needs a deep resource with real throughput — a rising water table, capillary rise, or fast weathering — not merely a deep reserve.

4H.4Root foraging — conquering free / richer soil (dynamic)

Roots are not static. Each tick a plant may extend a root voxel into an adjacent (cell, depth) when:

  • its current voxels are depleted or overcrowded (low per-capita grant), and
  • a neighbour voxel is less contested / richer (higher available ÷ rootMass), and
  • the move respects rootType limits (a taproot won't spread wide; a fibrous mat won't go deep) and obstacles (rockFraction, a rival's dominance).

It grows root mass there (paying energy) and retracts from exhausted voxels — root foraging, exactly how real plants proliferate toward nutrient patches. This is the "roots conquer other soil cells" behaviour. Bounded by maxRootVoxels so per-plant cost stays constant.

4H.5Who wins, who loses, who coexists (niche partitioning)

Outcomes emerge purely from voxel overlap + root type — nothing scripted:

  • Same type, same voxels (two fibrous plants in one topsoil voxel) → hard competition; more root mass / lower Km wins → the other starves (loses).
  • Different depths (fibrous shrub in topsoil + taproot tree in subsoil of the same cell) → they draw from different voxels → little overlap → coexistence (vertical niche partitioning — a real driver of high diversity).
  • Crowded cell → foraging pushes some plants' roots laterally into freer neighbour cells → spatial partitioning relieves the pressure and lets more individuals persist.

So dominance, exclusion, and coexistence all fall out of the geometry.

4H.6Cost

Uptake now gathers over V root voxels/plant (bounded = lateral cells × Nd): O(N·Nk·V). Canopy footprint f (shading) and root footprint V (uptake) are tracked separately. Still linear — see 5.

4IGrowth geometry, the energy budget & self-pruning

Growth is driven by energy, bounded by energy, and shaped by allometry — so a tree thickens and rises gradually, stops before it grows "like crazy," and dies when upkeep outruns income. Every formula is per-species and configurable; growth need not be linear.

4I.1Establishment & penetration power (seed vs. substrate)

Every organism has a penetrationPower (force to drive its radicle/roots in), and every cell surface a substrateHardness:

penetrationPower  = penBase(rootType) · g(size, energy)   // taproot ≫ fibrous; rises with size
substrateHardness = hardness(material, rockFraction)      // rock high · soil low · litter/nurse-log ≈ 0
establish (germinate, or root into a voxel) ⇔ penetrationPower ≥ substrateHardness
  • A seed lodged against rock: its penetrationPower is tiny → < rockHardness → it cannot root, dies, and decomposes (nutrients return to the cell, 2.5).
  • The same seed on leaf litter, soft debris, soil, or a nurse log (hardness ≈ 0) → establishes and grows.
  • Since penetrationPower rises with size, a mature taproot later cracks hard/ compacted layers a seedling couldn't — root foraging (4H.4) is gated by the same test. Hard ground therefore filters the flora — emergent, not scripted.

4I.2Allometric growth — height, diameter, crown, surface (configurable)

4I.2aThe three canopy quantities — never conflate them

Earlier drafts used one word, canopy, for three physically different things, and it caused real bugs (see 2.2). They are now separate, and each has exactly one job:

A_c = a_c · A_ref · (W/B_ref)^{p_c}        // crown spreads with WOOD          [m²]

A conifer and an open-crowned acacia can have the same A_c and utterly different A_l — that difference is the species. Collapsing them into one canopy number makes it impossible to express a sparse, light-passing crown, and it is what let a raw leaf area leak into the Beer–Lambert exponent in 2.2.

Cell-level LAI (what actually attenuates light) is the sum of the leaf area every overlapping crown drops into that cell, divided by the cell's ground area — see 2.2. Do not confuse plantLAI (one plant's crown density) with LAI(cell) (the stacked total above a patch of ground).

Retired name: the PlantAgent.canopy field is gone. Use leafArea and crownArea. The word "canopy" now survives only in spatial senses — "canopy footprint" (the set of cells a crown covers), "canopy layer/stratum", "canopy gap" — never as a quantity.

Growth accumulates plant carbon B from the energy budget. Physical dimensions follow from the woody part W = B − leafC by per-species allometric power laws (how real trees scale), so the trunk thickens and rises smoothly:

W           = B − leafC                        // [kg C] wood: stem, branch, root
height      = h_ref · (W/B_ref)^{p_h}          // [m]
diameter    = d_ref · (W/B_ref)^{p_d}          // [m] trunk girth (DBH)
crownArea   = A_ref · (W/B_ref)^{p_c}          // [m²] ground the crown covers
leafArea    = leafC · SLA                      // [m²] a STATE, not a formula (4I.2b)
trunkFootprint = π·(diameter/2)²               // [m²] how much of the cell the trunk fills

Stature is built from wood, never from total carbon, and this is not a detail. A deciduous tree drops every leaf it has and must be exactly as tall in January as it was in August. If height read total carbon it would shrink each autumn and regrow each spring — an accordion, not a tree — and the bug would be invisible in any annual summary, because by the time you looked it would have grown back. Wood is never shed, so height and crownArea are monotonic under this split; only carbon starvation (4I.3), which burns structure, can shorten a plant.

(Normalized power laws — 0.3.4. p_c ≈ 2·p_h, since crown area scales roughly as height².)

  • When trunkFootprint nears cellArea, the trunk fills its cell and the canopy footprint (3.6) expands into neighbours — the tree shades/occupies more cells and rises through more strata (4G.1). "Covers more area, width, and height," emerging as B climbs.
  • growthCurve (per species) picks the shape vs. age/size: linear, logistic (sigmoid — the default; slow → fast juvenile → plateau), exponential-saturating, or raw allometric. So growth is configurable and not forced linear. The plateau is not only a hard maxHeight clamp — it emerges from the budget below.

4I.2bFoliage is a POOL, not a formula

leafArea = Λ · crownArea made leaf area a pure function of biomass. That single line was load-bearing for four things that could not be written while it stood:

BlockedWhy
Leaf sheddingSubtract the foliage and the geometry recomputed leaf area from B and restored it on the next read. A seasonal "LAI multiplier" would have been a second, parallel fiction, and the carbon would never have gone anywhere — the tree would lose leaves without the leaves becoming anything.
Allocation to shootalloc.shoot was computed every tick and read by nothing, so shifting carbon to roots cost the plant no leaf area at all.

State. leafC [kg C] is foliar carbon, held as a subset of B rather than as a separate ledger account — so birth, death, litterfall and recruitment paths are untouched and conservation (6) stays structural.

A_l          = leafC · SLA                                  // leaf area          [m²]
targetLeafC  = min( Λ · A_c / SLA , leafMaxFrac · B )       // what it aims for   [kg C]
want         = (target − leafC) · (1 − e^{−k_build·dt})     // gap closed per tick

⚠ Leaf construction is funded from RESERVES, never from current growth

Writing this as a slice of positive net growth (min(dB, want)) makes it a ratchet: whenever dB is zero — night, winter, deep shade, a nutrient shortage — turnover removes foliage and nothing rebuilds it, which lowers assimilation, which makes dB zero more often.

It is invisible in every open-grown test, because a well-lit plant nearly always has dB > 0. Measured: Picea abies alone lost 35 %, while a boreal stand of it collapsed 82 % with LAI 0.73 → 0.16. Constructed directly, a plant stripped to 10 % of its canopy and holding 13.8 kg C of reserves against a 2.0 kg C target sat in the dark for 60 days and its canopy only decayed (0.1835 → 0.1553) while the reserves went untouched.

A deciduous tree flushes its entire spring canopy from stored carbon, before it has any photosynthesis at all — that is what the NSC buffer is for, and 4I.3 already describes it as paying for "next spring's budburst". The floor is not zero: a plant that spends its last sugar on leaves has nothing left to respire tonight and dies before they open.

  • Foliage is served first out of growth. Leaves are the only organ that earns, so a defoliated plant rebuilding its canopy before adding wood is doing the thing that pays. It is self-limiting without a cap: the target is set by crown area, crown area by wood, so a plant spending everything on leaves stops raising its own target.
  • leafMaxFrac is a structural floor, not a knob. Below ~0.05 kg C the derived target exceeds the plant's entire mass — a seedling would be more leaf than plant.
  • Realized crown density sits below Λ, and should. Foliage is always turning over, so a real canopy never quite reaches its own ideal. The pre-5A model held that unreachable ideal permanently, and for free.
  • max(leafLife, 365) — see the note in 4I.3.

4I.2cThe evergreen/deciduous trade-off is derived, not declared

There is no evergreen flag in this model and there must not be one. leafLifespan < 1 yr is deciduous and > 1 yr is evergreen — that is what the words mean. Two measured traits per species fix the annual price of holding a canopy:

⚠ A deciduous tree flushes ONE canopy a year, not two. Exponential turnover with mean lifespan L implies 365/L replacements per year, so leaves living 182 days would be charged for two canopies annually. A real deciduous leaf's life is bounded by the length of the growing season, not by attrition. Until phenology exists (4L.x), replacement is capped at once per year — evergreens are untouched, since their lifespan already exceeds a year. This cap is scaffolding for a missing mechanism and comes out when an explicit spring flush and autumn drop enforce one canopy per year by construction.

4I.3The energy budget — why growth self-limits, and why old trees die

The anti-runaway mechanism is physical, not a magic cap: income scales with surface, upkeep with volume.

gain = A · leafArea · L[crownLayer] · captureEff                   (~ B^{2/3} — a SURFACE)
cost = m·B_ref·(W/B_ref)^q · Q10^((T−Tref)/10)  +  t · height · (A_l/A_ref)   (~ B^{1} — a VOLUME)
net  = gain − cost                                                 [kg C day⁻¹]

Maintenance is charged on WOOD (W), not on total carbon, and foliage is deliberately left out of it. Charging respiration per unit leaf area was tried and measured: it made the shade-tolerance trade-off strictly worse (open-grown intolerant:tolerant ratio 1.43 → 0.98 as the coefficient rose), because leafRespFrac · A · A_l scales exactly like gross assimilation and is therefore a flat tax biting hardest on whoever has least margin — the light-demanding species. Foliage instead costs what foliage actually costs: it has to be built, and rebuilt as it turns over (4I.2b). That cost scales with leaf turnover, so it discriminates between an evergreen and a deciduous strategy rather than taxing both equally — and it moved the same ratio 1.833 → 2.248, into the published 2–4× band, with nothing tuned.

(Note the normalized (B/B_ref)^q — never raise a dimensional quantity to a fractional power; see 0.3.4.)

  • Leaf surface (B^{2/3}) grows slower than living volume/mass (B^{1}), and a taller trunk costs more to lift water (t · height · A_l/A_ref). So cost/gain rises with size until net → 0 — growth asymptotes at an emergent maximum, at roughly B* = (A/m)³ (10.6). maxHeight is only a safety clamp, never the real limit.

Why the A_l/A_ref factor on the transport term. The cost of lifting water is (how much water) × (how far up), not (how far up) alone. Written as a bare t · height the term is size-independent: a 2 m seedling pays the same to raise water 2 m as the lowest 2 m of a 60 m giant. For a seedling that single term then dominates its entire carbon budget and kills it, and the model reads as "growth doesn't work" while the bug is in the upkeep side. Verified in the reference implementation (ref/).

  • A second, independent ceiling comes from hydraulics: a taller tree must pull water up a longer column, so ψ_leaf falls toward ψ_crit (4J.2). Real trees are limited by both, and so is this model.
  • Ageing efficiency decline: captureEff(age) = captureEff₀·(1 − senescenceRate·age). Even at stable size, ageing drives net negative → upkeep unmet → stress climbs → senescence and death (4 step 6, then deadfall 4G.5). This is "the creation/retention of energy efficiency drops, so the plant dies," quantified.

4I.5Damage & self-pruning — heal a branch or drop it

Damage (herbivory, storm, disease, a crushing log 4G.5, or just deep shade) hits parts of the crown. The tree runs a cost–benefit per organ:

branchNet = branchGain(localLight) − branchMaintenance − (damaged ? healCost : 0)
  • Deep-shaded lower branch (below its light-compensation point): persistently negative → drop it (abscission) — stop paying upkeep, reclaim some nutrients. Why trees self-prune bare lower trunks — emergent.
  • Damaged but well-lit branch: heal iff healCost < discountedFutureGain, else drop.

Cheap default (no per-branch agents): shed the crown fraction below the compensation point → leafArea shrinks (crownArea lags), net recovers. Model individual branches only for hero trees (branchDetail flag; adds a small O(N·branches) term, 5).

4I.6The master growth equation (polynomial form + species & calibration constants)

Every driver feeds one assembled expression. Each driver x_j (light, water, nutrient_i, T, CO₂) contributes a response term g_j(x_j); the species supplies the constants. In the most general polynomial form:

g_j(x_j) = clamp( Σ_{k=0..n} a_{j,k} · x_j^k , 0, 1 )       // per-species polynomial coeffs a_{j,k}

(Saturating drivers use the rational Monod/Michaelis form x/(K+x) — a special case; prefer it as the default, because raw high-order polynomials blow up or go negative. The polynomial is the general superset for when you want a custom hand-shaped response.) The full per-tick equations:

A_l (leaf) = Λ · A_ref · (B/B_ref)^{p_c}                     // leaf area, NOT crown area [m²]
φ_nutrient = min_i g_{N_i}(reserves_i)                       // Liebig limiter (3.3)
P (gain)   = A · surface(B) · (Π_j g_j(x_j)) · φ_nutrient · captureEff(age)   [kg C day⁻¹]
M (upkeep) = ( m·B_ref·(B/B_ref)^{q} + t · height(B) · A_l/A_ref ) · Q10^{(T−Tref)/10}  [kg C day⁻¹]
net        = P − M + c1                                      // c1 = calibration offset (11.2)
ΔB         = η · max(0, net) · Δt                            // [kg C]  — Δt in DAYS
Δτ (trait) = ΔB · allocFrac[τ] · (W[τ]·reserves)/Σ(W·reserves) + c2_τ
             //   allocFrac from 3.7 (adaptive), W from 3.4 (species identity)
  • A, a_{j,k}, a_c, p_c, m, q, t, η, W are species constants — different tree = different set = its own "ultimate equation."
  • c1, c2_τ are calibration constants: we cannot copy nature exactly, so these absorb the residual — the effects we didn't model — fitted so the sim's output matches observed growth curves. Default them to 0 and treat a non-zero value as a warning light, not a tuning layer. c1 is literally an unexplained carbon source: it will break the conservation law of 4C unless you book it against a real pool, and a large one means a missing mechanism, not a missing constant. 11.2 gives the rules that govern them (bound |c1| < 0.05·P, book it as a flux, and always report it).
  • Every symbol here is a real, exposed parameter (6.2) — this equation is the 0.1 run-order, written as one assembled formula.

4I.7Modeling approach — is "a tree = an equation" the right idea?

Yes as the backbone — but stated precisely: a tree is a small state vector evolved by a parameterized set of equations (a dynamical system), with the same template for every species (only the constants differ, 4I.6). It is not one monolithic equation. This process-based framing is the only paradigm that scales to thousands of organisms all reacting through the shared fields, stays deterministic (4A), and is fully data-driven. Alternatives, and why we don't use them as the base:

ApproachTree is…Trade-off

The recommended design is a hybrid, separating function from form via LOD:

  • Physiology (grow? how much? die?) — equations, on every organism, everywhere. This is what makes the world react. Cheap and linear (5).
  • Architecture (the visible 3D shape — trunk, branches, crown) — a procedural / parametric or light L-system layer driven by the equation outputs (biomass, height, diameter, crownArea, leanVector), instantiated only at high LOD (near player / hero trees). Distant trees = equation state + an instanced mesh keyed to biomass/stage (UE5 HISM/foliage). So we get a lightweight functional-structural model with aggressive LOD — form where it's seen, function everywhere.

Where pure equations are weak — exact discrete topology (one specific branch snapping, the precise shadow of a gnarled crown) — we either approximate statistically (the shed-fraction self-pruning of 4I.5, the shadow-splat of 4G.2) or let the procedural architecture layer handle it up close. Net: the equation model owns behavior and scale; the structural layer owns appearance.

4JWater relations — transpiration, stomata & the cost of carbon

This is the largest single gap in the earlier draft. Water appeared as a resource that plants drank, and K⁺ was documented as governing "stomatal regulation" — but nothing in the model ever opened a stoma, and no plant ever lost water. Photosynthesis simply read waterReserve as a multiplier. That misses the central trade-off of terrestrial plant life:

A plant cannot take in CO₂ without letting water out. The same pores (stomata) admit carbon and leak water. Every gram of carbon a plant fixes is paid for in hundreds of grams of transpired water. This trade-off is why deserts look different from rainforests — and without it, drought in our model is just a mild growth multiplier instead of the thing that kills plants and sets biome boundaries.

4J.1Stomatal conductance — one dial, two consequences

The plant controls one variable, g_s (stomatal conductance, mol m⁻² day⁻¹). Opening it raises carbon gain and water loss together:

g_s   = g_max · ( g_min + (1−g_min) · f_water(ψ)·f_K(K⁺)·f_vpd(VPD)·f_light(L) )
P     = A · A_l · (g_s·co2)/(Kc + g_s·co2) · Π g_j · φ · captureEff   // CO₂ enters through g_s
Tr    = g_s · A_l · VPD · M_W                                          // H₂O leaves through g_s

(M_W = 0.018 kg mol⁻¹ converts the molar water flux to kg H₂O — so Tr lands in kg H₂O plant⁻¹ day⁻¹, matching waterReserve in 0.3.2.)

  • f_light — stomata open in light and shut in the dark. Omitted from the earlier draft, and its absence is expensive in two directions: every plant transpires at full rate all night for zero carbon gain, and a deeply shaded understory pays the same water bill as the canopy shading it. Stand water use came out several-fold too high, and being suppressed came out cheap when in reality it is the entire cost. Drive it from the light the crown actually receives (4G.1), not from sunlight.
  • g_min — the leak a leaf cannot close (cuticular conductance, ≈ 1–5 % of g_max). Small, and load-bearing: with perfect closure the plant is perfectly isohydric, shuts down before tension can ever build, and hydraulic failure becomes impossible by construction — ψ_crit, R_stem and R_root all go dead, and drought can only ever kill by carbon starvation. Real leaves leak and real trees embolise; 4J.2 promises both pathways, so g_min > 0 is what makes the second one reachable.
  • VPD (vapour-pressure deficit) is the drying power of the air — derived from temperature and humidity; hot dry air pulls water out far faster.
  • f_K(reserves[K⁺]) is where potassium finally earns its keep. K⁺ drives the guard-cell osmotic pump; a K⁺-deficient plant cannot regulate its stomata, so it either wastes water or fails to open for carbon. The 3.1 claim "K⁺ = water regulation, drought tolerance" is now a mechanism rather than a comment.
  • Water-use efficiency WUE = P / Tr is now an emergent, measurable species property — and it is a real number ecologists publish, so it is a calibration target (12).

4J.2Water potential & hydraulic failure (how drought actually kills)

ψ_soil = ψ_e · (θ / θ_sat)^(−b)                  // Campbell; b ≈ 4 sand … 9 clay
ψ_leaf = ψ_soil − (Tr / A_sap) · (R_root + R_stem·h)   // A_sap = A_l/A_ref, the PIPE MODEL
if ψ_leaf < ψ_crit(species):   cavitation → lose conductivity → g_s collapses
  • Resistance is per unit conducting capacity (A_sap), not absolute. A bigger plant has built more xylem, so its resistance falls in proportion — the classic pipe model. Without the division, tension grows with leaf area and every tree above sapling size embolises permanently: our reference implementation reached ψ_leaf = −254 MPa, against a real xylem range of about −0.5 to −4. Dividing by it leaves tension depending on g_s, VPD and height, which is the physically interesting part.
  • Tall trees have a longer hydraulic path (R_stem·h) → they run at more negative ψ_leaf → height is hydraulically limited, which is a second, independent ceiling on tree height alongside the carbon ceiling of 4I.3. (It is the leading explanation for why the tallest trees stop at ~115 m.)
  • ψ_crit (embolism resistance) is a genuine species strategy axis: an isohydric plant shuts its stomata early and starves safely; an anisohydric plant keeps them open, keeps fixing carbon, and risks hydraulic failure. Both strategies exist in nature and now both exist here — from one parameter.

The exponent b is the whole point — do not simplify it to 1/θ. We did, and at 35 % available water it gave −0.09 MPa where the real value is near −1. Soil potential then never approached any woody ψ_crit, and a hot dry site came out less water-stressed than a temperate wet one — backwards. The power law is what makes drought a cliff rather than a slope: potential collapses non-linearly as the last water goes, which is why an ecosystem can look fine until days before it does not. Clamp at a floor around −3 to −4 MPa (real soils get there); clamping at the −1.5 MPa conventional wilting point means soil alone can never break a woody plant.

  • Drought mortality has two distinct pathways, and the model reproduces both: carbon starvation (stomata shut → net < 0 → E drains → 4I.3 death) and hydraulic failure (ψ_leaf < ψ_crit → the plumbing breaks → rapid death). Which one gets you depends on your strategy — an active question in real ecology.

Cost: two extra scalars per plant, no new loops — folds into Pass C. Setting g_s = 1 and Tr = 0 recovers the old water-free behaviour exactly, so the prototype can defer this.

4KPhenology, dormancy, resorption & the seed bank

Seasons were previously felt only as continuous changes in light and temperature. But real plants don't respond continuously — they respond to thresholds and cues, and they anticipate. Three cheap additions make the annual cycle real.

4K.1Growing degree days (the standard phenological clock)

Development is driven by accumulated warmth, not by calendar date:

gdd += max(0, T − T_base) · Δt              // °C·day; reset each year at day 0
budburst   when gdd > gddBudburst  AND  chillingDays > chillReq   // spring
leafDrop   when photoperiod < criticalDaylength  OR  T < frostThreshold  // autumn
  • chillingDays prevents a warm January from tricking a tree into leafing out — real temperate trees require a cold period before they can respond to warmth. This is also the mechanism through which climate warming damages forests in the model (climateDrift, 4A.4): insufficient chilling → erratic budburst.
  • Photoperiod (not temperature) triggering leaf drop is why autumn happens on schedule even in a warm year. daylightFraction (4A.1) already gives us this for free.
  • GDD is the standard phenology model in agronomy and forestry — using it means our species parameters can be taken straight from published tables (10).

4K.2Nutrient resorption — plants don't throw nutrients away

Before dropping a leaf, a plant withdraws roughly half of its nitrogen and phosphorus back into storage. Skipping this makes deciduous trees absurdly wasteful and, worse, wrecks the litter chemistry:

reclaimed_i        = resorptionEff_i · tissue_leaf[i]     // ~0.5 for N and P, ~0 for Ca
reserves[i]       += reclaimed_i
organicNutrients[i] += tissue_leaf[i] − reclaimed_i        // the rest falls as litter

The consequence chains straight into 2.5.1: resorbed litter has a much higher C:N ratio → decomposes more slowly → nutrients cycle more slowly. So a nutrient-poor site drives harder resorption, which produces poorer litter, which makes the site poorer still — a self-reinforcing poverty trap that is one of the best-documented feedbacks in real ecosystems, and it emerges here from one line.

4K.3Dormancy

A dormant plant sets g_s = 0, drops its leafArea to ~0, and drops maintenance to a low dormantMaintenance — it must survive the winter on its NSC reserve E. This makes E (0.3.3) load-bearing rather than decorative: a tree that entered autumn with a depleted reserve (because it was shaded, or defoliated, or grew too aggressively) does not wake up in spring. Winter mortality becomes a consequence of the previous summer's budget, which is exactly how it works in the field.

4K.4The seed bank

Seeds that fail to germinate should not silently vanish. Each cell carries a small seedBank[species] count with a per-year seedViability decay. Seeds germinate when their cue is met (light gap, fire, moisture, cold stratification). The payoff is large: a cleared or burned patch re-vegetates from the bank instead of waiting for dispersal, which is exactly how real post-disturbance succession works — and it is the mechanism that keeps rare species alive through bad decades (a "storage effect", a recognized coexistence mechanism). Cost: one small array per cell.

4LDisturbance regimes — the missing engine of diversity

A world with no disturbance converges to a monoculture climax and stays there forever. Whichever species is best at the local soil wins, shades everything out, and the simulation goes quiet. This is not a modelling nuisance — it is a genuine prediction of an incomplete model, and it is wrong, because real ecosystems are disturbance-driven. Gaps, fires, and storms are what keep pioneers in the world at all, and the intermediate-disturbance principle (peak diversity at moderate disturbance) is one of the strongest patterns in ecology.

4L.1Patch disturbance is what actually closes the canopy

The Extent field above is not cosmetic — it decides whether a forest can have a closed canopy at all. The earliest implementation made a disturbance a stand-wide cull: every stem in the cell faced the same mortality draw on the same tick. On a single cell that is catastrophic — a ~5-year return interval at ~45 % severity resets the whole stand roughly every decade, so it never matures past a ~10 m scrub and the forest floor stays bright (~60 % of open-sky light). Succession still ran in composition, but the physical canopy never closed.

The fix is to honour the patch extent: a disturbance opens a local gap of radius distPatch at a random point, and only the stems inside that gap are exposed. The matrix between gaps keeps growing, so the canopy stays closed while gaps cycle the climax in — which is what a real treefall does. Turning this on takes the closing forest biomes from bright scrub to a genuine closed canopy (floor ~40 %, leaf-area index ~3–4, canopy height ~15–25 m) while preserving the gap-phase succession the pioneers need. It is landed off-by-default (radius 0 = the old stand-wide behaviour = golden bit-identical) and enabled on the three closing forest biomes; the open biomes (grassland, and the fire-maintained Mediterranean) are meant to stay open and leave it off.

One lesson from enabling it is worth stating as a rule, because it recurs: a composition result that flips wildly from one random seed to the next is often a symptom of an incoherent species pool, not a mechanism that needs tuning. The montane-conifer biome was stocked with species from two continents that never actually compete; under patch gaps their balance was bistable, and no gap size stabilised it. Replacing the pool with a coherent regional flora (4F) dissolved the instability into a single seed-robust climax. The honest fix was upstream, in the data, not downstream in the gap parameter — the same discipline as 9.3.

4MMycorrhizal networks — how trees actually "share"

Your very first requirement was that trees "compete, share, and so on." Competition got a full treatment (3.2.1, 4H.5). Sharing was never actually specified — it was mentioned once in the design doc and then lost. Here it is, and it is real biology, not a fairy tale: ~90 % of land plants trade with mycorrhizal fungi, and those fungi link multiple plants into a common network.

4M.1The symbiosis (a trade, not charity)

The fungus is far better at scavenging soil than roots are (its hyphae are thinner and reach further); the plant is the only one who can fix carbon. So they trade:

plant → fungus:  carbonTax · P              // typically 10–30 % of the plant's whole carbon gain!
fungus → plant:  boost to uptake — modelled as
                 Vmax_i_eff = Vmax_i · (1 + mycoBoost_i · fungalBiomass)
                 Km_i_eff   = Km_i   · (1 − mycoScavenge_i)     // reaches lower concentrations

The trade is conditional, which is what makes it interesting: on rich soil the carbon tax outweighs the uptake gain and the plant down-regulates the symbiosis; on poor soil (especially P-poor) it is decisively worth it. So mycorrhizal dependence becomes a soil-fertility-dependent strategy rather than an on/off flag — and it explains why fertilizing a forest can reduce fungal networks.

4M.2The network (where sharing happens)

Fungal mycelium in a cell links the plants rooted there (networkId). Across a network, a small fraction of surplus carbon flows down the source→sink gradient:

for each network:
    surplus_p = max(0, E_p − reserveTarget_p)          // who has spare NSC
    deficit_p = max(0, reserveTarget_p − E_p)          // who is starving (a shaded seedling)
    transfer  = shareRate · min(Σ surplus, Σ deficit)  // shareRate is SMALL: 0.01–0.05
    distribute proportionally: donors give ∝ surplus, receivers get ∝ deficit
    minus transferLoss (the fungus takes a cut — sharing is never free)

Guardrails, because this is easy to get wrong: shareRate must be small and the loss real. Nature does not run a socialist forest — the transfers measured in the field are modest, and a model with generous sharing produces an absurd world where nothing ever dies of shade. Set shareRate = 0 (the default) and the network vanishes cleanly.

What it buys you: shaded seedlings survive in deep shade on a subsidy from the canopy (the "nurse tree" effect, and a real observed phenomenon) → the understory is populated rather than dead → when a gap opens (4L), an advance regeneration cohort is already standing there, primed to shoot up. That is how real forests replace themselves, and it needs the network to work.

Cost: networks are per-cell groups; the transfer is one pass over network members, O(N) total. Kept deterministic by computing all surpluses before any transfer — the same two-phase discipline as 3.2.1.

4M.3Status — built, measured, and two things this section got wrong

Both halves are implemented (mycoTax, mycoBoost_{N,P,K}, mycoScavenge, K_myco, mycoTurnover, shareRate, transferLoss), off by default and bit-identical to the golden oracle. The fungal carbon is a real ledger pool (soil.mycorrhiza); turnover and host death route it to soil organic matter as necromass. Two changes to what is written above were forced by measurement, and one prediction it makes is confirmed.

Confirmed — the conditional trade, with a measured sign change. What a plant pays is mycoTax × gross assimilation × how empty its scarcest nutrient reserve is, so the down-regulation on rich soil is a consequence of internal status rather than a rule. On a phosphorus gradient (both seeds agreeing at every point), the symbiosis raises stand biomass by +110 % on the poorest ground and costs 25 % on the richest, crossing over between 1.4 and 6.0 g P m⁻². The Liebig factor phi explains it exactly: the partnership pays when (1 − phi) > mycoTax, i.e. when the limitation it relieves is deeper than the price it charges. Colonisation falls 57–60 % from the poorest site to the richest — fertilizing a forest does shrink its fungal network.

Corrected — the source of a network transfer is the mycelium, not the donor's NSC. 4M.2's surplus_p = max(0, E_p − reserveTarget_p) assumes spare sugar sits in the plant. It does not: measured across a 15-plant stand holding ~200 kg C, total surplus NSC was 0.0005 kg C and exactly zero on five ticks in six, because allocation drains E to the buffer target every tick. Written that way the network moved 3.3 kg C in thirty years. Sourcing it from the standing fungal pool — carbon the plant has already handed over, which growth cannot reach — is both effective (19–75 kg C per 30 yr) and the better physics: the transfers measured in the field are of recently fixed carbon moving through hyphae, not of a tree exporting its winter reserves.

Corrected — "what it buys you" does not follow, and the reason is not in this section. 4M.2 claims the payoff is shaded seedlings surviving on a subsidy, giving an advance regeneration cohort. Measured over six seeds with a time-integrated statistic, there is no rescue (−4 % seedling-years; better on one seed of six) even though 61 % of the delivered carbon reaches the understory. The cause is that nothing in a suppressed understory dies of carbon starvation: of 19 deaths, ten were enemies, five suppressed and four background, and none were carbon. Suppression mortality is a hazard keyed on shade (4N), deliberately — at equilibrium every plant in a crowded stand has RGR ≈ 0, dominant and suppressed alike, so a growth-rate trigger would kill the canopy. A carbon subsidy cannot buy survival from a hazard that does not read carbon. The payoff this section promises therefore requires suppression mortality to route through the carbon budget; that is a change to 4N, not to 4M, and it is not made here. The same measurements retire this section's guardrail worry from the other side: across its whole range the network is nowhere near strong enough to make the understory immortal.

4NDemography — establishment limitation & density dependence

Two population-level effects that individual-based models routinely forget, and whose absence shows up immediately as implausible forests:

  • Establishment limitation. A seed landing on a suitable cell should not automatically become a plant. Real seedling survival in year one is often < 1 %. Add establishmentProb = f(light, moisture, litter depth, substrate 4I.1, predation). Without it, seed rain converts to stems nearly 1:1 and the forest becomes an impossibly dense thicket.
  • Self-thinning. As a cohort grows, competition kills the losers, and real stands follow the remarkably robust −3/2 self-thinning law: mean biomass ∝ density^(−3/2). We do not impose this — it should emerge from resource competition. It is therefore one of the best validation targets we have (12): if your simulated even-aged stand traces a −3/2 slope on a log–log plot of mean mass against density, your competition is quantitatively right. If it doesn't, something in the light or uptake apportionment is wrong. This is a genuine falsification test.
  • Density-dependent mortality beyond resources (the pathogen term of 4L) supplies the negative feedback that lets rare species persist.

4OAllelopathy & chemical fields (optional)

Some plants poison their competitors (walnut, eucalyptus). This needs no new machinery — it is one more diffusible field with a decay term, produced by a MetabolicReaction (4E) and read as a g_j multiplier in the master equation:

allelochem[cell] += production · B  −  decay · allelochem     // one more diffusing scalar
g_allelo = 1 / (1 + allelochem / tolerance_species)           // resistant species set tolerance high

Costs O(G) per chemical. Listed here mainly to demonstrate the point of 4E: an entire ecological mechanism gets added as data plus one field, with no engine change. The same slot handles pollution, pesticide, or an alien toxin.

Extrapolate and net peaks, then turns negative → senescence.
  3. No runaway. The plant can't grow "like crazy": once the cell's nutrient pool is mined (tick 4), it runs on reserves that now drain ~0.3/tick against a 0.1 weathering trickle — a finite runway. When reserves fall enough, φ and P collapse, net<0, and the tree dies and becomes a log (4G.5) that decomposes and refills the very soil it emptied — closing the loop.
  4. Where calibration constants would enter: if a real seedling of this species grows, say, 15% faster early on, you don't rewrite the model — you nudge c1 (or η) until the tick-1–3 curve matches, leaving the mechanism intact.

(Extending to two plants just runs step 1 as the shared two-phase split — both compute demand, the soil is divided in proportion to root mass, and the one with lower Km keeps a positive net longer on the thinning soil: that is who "wins," 3.2.1/4H.5.)

4QThe heterotroph layer — condition, herbivory, consumers & animals

Everything above models an autotroph: a plant fixes carbon, spends it, and dies. But a plant is one kind of organism, and the same carbon-currency, conservation-ledger and trait-derived machinery generalises to the rest of the food web. This section adds four layers, each a separate switch, off by default, and bit-identical to the golden oracle when off (13.4) — a mechanism is added, never a number tuned. Every gram still moves through the ledger (3A), so no bite, birth, move or death can create or destroy matter.

4Q.1Condition — the general integrity state (§H)

Alongside the specialised recovery states the model already carries (embolism/embolRefill, 4J; carbon-deficit stress/mortMemory, 4N), every organism gets one general health scalar condition ∈ [0,1] (1 = intact). It is damaged by any insult and healed from reserves — the reusable core of being an organism:

deficit   = max(0, maintenance − uptake)                  // unmet carbon demand this tick
condition −= damageScale · deficit / B                    // insult lowers integrity
heal       = min(healRate · (1 − condition), E_available) // repair, paid from NSC reserves
condition += heal · (1/healCost);  E −= heal              // reserves respired to CO₂ (conserved)
P  *= condition                                           // a sick organism grows slower (4I)
if condition ≤ conditionMort: die(cause = "decline")     // and eventually dies

Gated on healRate > 0: at zero, condition stays 1.0 and nothing draws reserves or RNG — the plant model is untouched. Damage and healing are conservation-exact (the heal cost is NSC respired to the atmosphere, 3A).

4Q.2Herbivory & the growth–defense trade-off (§H1)

The first external damage source. A master rate herbivoryRate removes leaf to litter each tick; a per-species defense ∈ [0,1] reduces the loss but costs carbon:

loss    = herbivoryRate · leafC · (1 − defense) · Δt      // defended leaves are eaten less
leafC  −= loss;  soil.organic += loss                     // eaten leaf → litter (or a consumer, 4Q.3)
grow_cost = defenseCost · defense · leafC · Δt            // defense is not free — carbon not grown
condition −= f(loss)                                       // and the wound lowers integrity (4Q.1)

defense is derived from the leaf-economics spectrum (4B, 10), not tuned: long-lived, tough leaves (evergreen conifers) map high, cheap deciduous pioneer leaves low. So the trade-off — a pioneer grows fast and is eaten, a conifer is armoured and slow — emerges from one existing trait. Validated: undefended pioneers collapse under herbivory while defended evergreens hold (12).

4Q.3The consumer interface — one place to add an organism that eats another

Rather than hard-code each herbivore, consumers are a registry (mirroring the user-equation registry, 4E) with a strict two-tier portability contract so the oracle survives (13.4):

  • Tier 1 (portable) — a consumer declared purely by numbers (target, tissue, grazeMax, K_forage, assimEff, maint, turnover, cn, wound). Deterministic and re-implementable from the values alone.
  • Tier 2 (non-portable) — an arbitrary intake_fn(cell) → kg C intended for a research spike; it still only returns an amount, the engine applies it, and the oracle harness refuses to run once one is registered.

A consumer declares intent; the engine moves the mass through the ledger, so an organism author cannot break conservation even by accident. Intake follows a Monod functional response on the palatable target tissue:

avail  = Σ_plants  tissue_pool · (1 − defense)                    // palatable target in the cell
intake = grazeMax · body · avail/(avail + K_forage) · Δt          // saturating, clamped to avail
body  += intake · assimEff                                        // assimilated → consumer body
soil.organic += intake · (1 − assimEff)                           // the rest → frass (N,P,K follow C)

4Q.4Discrete animal agents — individuals, mobility & a second trophic level

The per-cell consumer pool above is conservation-trivial but has no individuality or mobility. An Animal agent (parallel to a plant agent) carries its own body (C, N), position, age, and condition; its diet is a registry entry (4Q.3). The key conservation move: the animal.body census sums over the agent list, not per cell, so relocation and birth move mass within one pool and need no ledger entry at all — only frass, carcasses and respiration cross a boundary.

FEED    body += _feed_body(diet, cell)          // same tissue dispatch as the pool (4Q.3)
RESPIRE body -= maint · body · Δt → CO₂          // the metabolic cost of staying alive
CONDITION  body shrank ⇒ starving ⇒ condition ↓ ; fed ⇒ condition ↑   // the 4Q.1 loop, on animals
BIRTH   body ≥ animalBirthMass ⇒ split a neonate off the parent's own body   // internal → no ledger op
MOVE    step to the grid-adjacent cell with the most forage (kinesis; explore when hungry)  // 1A grid
DEATH   starvation, senescence hazard (turnover + animalSenesc·age), or predation → carcass litter
  • Births & longevity give an individual-based population that booms and busts with no tuned setpoint. Validated: an unregulated herbivore irrupts and destroys its resource — the classic overshoot-collapse (12).
  • Mobility is a run-and-tumble foraging kinesis over the 2D cell grid (1A, animalMove>0): climb the food gradient into the richest von-Neumann neighbour, explore to a random neighbour across a foodless gap when hungry, hold when fed. A mobile forager tracks a patchy resource where a fixed pool starves — measured on a 3×3 grid, a cohort released in one corner with food in the opposite corner walks a genuine 2D path and aggregates on the food. (The default single-row layout reduces this to the earlier linear-chain movement, unchanged.)
  • Predators are simply an animal whose tissue = "prey": it eats other animal agents in its cell (prey body → predator + frass; a prey eaten whole dies to a carcass). This closes the loop plant → herbivore → predator. By default predation is a biomass continuum (graze the intake off the prey, leaving wounded survivors); Consumer.killWhole switches it to discrete whole-individual kills — the predator kills whole prey at the same functional-response rate (whole kills up to the intake budget, the last, partial victim killed by stochastic rounding), so every victim dies whole (no wounded), a realistic vertebrate kill. Measured: same kill rate, but the lumpy feast-or-famine intake makes the predator die sooner (it can starve through a kill drought), extra stochasticity that destabilises a small predator population. Off by default ⇒ bit-identical. Predator–prey coexistence in small discrete populations is fragile (stochastic collapse — the "atto-fox" effect). Sustained cycles classically want space, and the 2D mobility above supplies it: measured on equal total area, a predator that dies out by year 1 in a single well-mixed cell persists 7–13× longer on a 5×5 grid with movement (both seeds tested) — the classic Huffaker spatial-refugia result, distributing prey so the predator is not instantly satiated-then-starved. It prolongs persistence rather than reaching indefinite coexistence: in that base study the predators still clump in one cell instead of dispersing to track the spreading prey.
  • A predator-tracking kinesis (forageInterference, 3B, default 0) was the obvious candidate to turn that prolonged persistence into sustained cycles — and it was measured, and it does not. With interference on, the forage an agent perceives in a cell is discounted by the same-kind foragers already there, perceived = food / (1 + forageInterference · n_competitors) — the canonical interference / ideal-free-distribution rule, so a crowded cell looks poorer and competitors spread across patches. It works mechanically: predators un-clump (occupied cells 1 → 10–17 on the 5×5) and genuinely track prey, so they find food in many cells and irrupt (population booms 2–3×). But the tighter coupling then busts within a few years in every case — no interference strength meaningfully beats the clumped baseline's persistence. This is the ecology, not a bug: the grid's persistence came from the imperfect tracking, the refugium mismatch of prey escaping to cells the predator hasn't reached. Remove the mismatch and the predator exploits every patch, prey has nowhere to hide, and the system overshoots faster. So the barrier to sustained cycles is not merely predator clumping; genuine Huffaker cycles want prey refugia the predator physically cannot enter, a larger edge-buffered landscape, or per-kind demographic lags — the remaining steps (9.4). forageInterference still ships as an off-by-default knob (it is a real, correct mechanism); its measured finding is simply that predator tracking alone is not the missing ingredient.
  • Per-kind demographics. A stable cycle also wants predator and prey on different clocks (fast-breeding short-lived prey, slow-breeding long-lived predator) — which a single shared clock cannot express. So every world-level agent rate (animalBirthMass / animalBirthRate / animalSenesc / animalStarve / animalHeal / animalMove / forageInterference) now has an optional same-named override on the consumer declaration; unset ⇒ falls back to the world value, so a kind that overrides nothing is bit-identical (golden 10/10, and the shared-clock control reproduces the pre-refactor predator persistence exactly). This too was measured, and separate clocks alone do not rescue coexistence in a closed grid: the intuitive split — a long-lived predator — is exactly wrong there, persisting long enough to eat the prey to extinction (a total collapse the shared clock avoided, since the prey survived on plant regrowth); making prey out-breed and out-run the predator failed too (with interference off the prey still clumps on the richest plant cell, so a predator finds it regardless). Same root cause as the tracking result: no per-kind rate manufactures a refuge that isn't there.
  • Landscape scale & a prey refuge (SoilCell.refuge, default 0). The last spatial candidate: a bigger landscape, or a prey refuge the predator cannot drain — the classic Rosenzweig–MacArthur / Huffaker stabiliser. refuge is the fraction of a cell's prey biomass a predator cannot reach (predation and the predator's foraging perception both see only 1−refuge of it; 0 ⇒ bit-identical). Both were measured, and neither rescues coexistence — and why not reframes this whole thread. A bigger grid bought only +2 predator-years for a 2.6× area (5×5 yr13 → 8×8 yr15). A refuge is a real, validated mechanism (refuge=1 everywhere ⇒ predators find no prey ⇒ extinct in year 1; refuge=0.5 halves the predator peak) but no setting yields sustained coexistence: a low refuge leaves more prey ⇒ a bigger predator boom ⇒ faster crash, a high refuge starves the predator, and the effect is seed-dependent (it can damp a severe overshoot, e.g. seed11 yr7→yr12, but never persists). The reason: every one of these mechanisms protects the prey, but in ECOSIM the prey never goes extinct — the herbivore sits on a renewable plant base, so it is already effectively refuged and prey extinction is simply not the failure mode. The failure mode is predator extinction from boom-bust overshoot plus post-crash clumping, which no prey-side stabiliser touches (more protection can even starve the predator faster). So the binding constraint is predator-side / functional-response — an overshoot-damping mechanism (predator satiation / handling time, a Type-III response giving low-density prey a behavioural refuge, or anti-clumping territoriality), a different scope from the spatial one (9.4). The refuge knob still ships off-by-default: it is a correct, broadly useful lever (protected patches / no-take reserves) that will compose with an overshoot-damped predator once that exists.
  • Predator functional-response shape (Consumer.forageHill, default 1). The predator-side candidate: the intake response grazeMax·bC·monod(density, K_forage) is a Holling Type II (near-linear at low prey ⇒ rare prey hit at full efficiency — the destabilising paradox-of-enrichment shape). forageHill is the Hill exponent (n=1 ⇒ the old Monod, bit-identical; n>1 ⇒ Holling Type III, the sigmoid xⁿ/(kⁿ+xⁿ) whose attack rate collapses super-linearly as prey get scarce, an emergent low-density prey refuge). Measured, and it does not rescue coexistence either — across shape, half-saturation, and even composed with a slow-starve energy buffer, the predator still goes extinct in ~5–14 years, because Type III only reshapes low-density behaviour but the predator dies from a synchronised clump-and-starve on a fast timescale (it eats the local prey out and starves in ~½ yr before the prey can rebound), and every lever trades off (a weaker predator starves, a stronger one over-exploits).
  • Capstone. Five candidates — tracking, per-kind demographics, landscape scale, prey refuge, functional-response shape — were built and measured to not yield sustained coexistence. That convergence is the result: it is very likely correct ecology, not a deficiency. Small, closed, discrete predator–prey populations go extinct — exactly what real ones do, and exactly Huffaker's own finding (his small simple mite universes always went extinct; only a large complex one with dispersal barriers and rescue oscillated). Sustained cycles are therefore not a missing mechanism but a missing scale + openness: a metapopulation large enough for out-of-phase local booms to rescue one another, and/or an open boundary so a local extinction is not permanent. Per emergence over tuning, the model was left to report this rather than be tuned into coexistence.
  • Open-boundary immigration (Consumer.immig, yr⁻¹, default 0) — the capstone confirmed. The prediction was that openness, not a sixth per-agent trait, is the missing ingredient. Built and it works: immig is the rate at which established individuals of a kind arrive from an external mainland; the immigrant is new mass from outside, booked external → animal.body through the ledger (conservation-exact, audited under check=True), and the rescue pass runs even when the grid's animals are all dead (a re-colonisation — the whole point). Measured on the same 5×5: the closed control still collapses (predator extinct yr13); one-sided predator immigration is destabilising at every rate — a subsidised predator never crashes and grinds the prey to extinction (apparent competition), inverting the closed outcome; but two-sided immigration (a modest predator rescue plus a prey source) yields the first sustained coexistence in the model — on both seeds the predator is present every year of a 30-year run and both populations oscillate in bounded cycles (prey ~24–92, predator ~2–20) with neither going extinct. This is the metapopulation / mainland-island rescue Huffaker's large complex universe supplied: five closed-system knobs could not produce coexistence and a boundary flux does. immig ships off-by-default (colonisation, source-sink, rescue). By default the mainland has global dispersal (an immigrant seeds a random cell); setting World.immig_edge makes the boundary physical — colonists arrive only at PERIMETER cells and spread inward. Measured: coexistence still holds under an edge-only boundary (the predator persists through genuine extinction→recolonisation rescues from the perimeter), and the geometry is validated (with arrivals pinned, edge-only puts 100 % of them on the edge vs ~33 % for random) — but at the rare rescue rates that matter the entry point barely reshapes the ecology, since immigrants are a tiny flux next to in-situ births. A faithful open-perimeter / colonisation-front option, off by default.
  • Local natal dispersal (Consumer.disperse, default 0) — the metapopulation coupling. Immigration seeds a random cell (global dispersal); a true metapopulation couples patches locally. disperse is the fraction of a kind's newborns that emigrate to a random grid neighbour of the natal cell — the animal analogue of plant seedSpread, a cell reassignment with no ledger op (off ⇒ bit-identical). Measured: local dispersal alone in a closed grid does not create coexistence — on a small grid it makes it worse, because strong dispersal SYNCHRONISES the patches (they boom-bust together), so the closed metapopulation collapses even faster (the textbook result: dispersal destabilises unless weak and the landscape is large enough to hold asynchronous phases). That confirms, from the other side, that the persistence ingredient is openness, not internal reshuffling. But disperse composes with the immigration rescue into a proper spatially-extended metapopulation: added to two-sided immigration it keeps the sustained coexistence and spreads the predator — which clumps (≈1 cell) under immigration alone — across the landscape (≤6 of 36 cells, prey ≤13), so the populations occupy the grid instead of piling into one patch. It supplies spatial structure, not persistence.
  • Landscape heterogeneity / dispersal barriers (World.set_barrier, default none). A per-edge movement permeability (World.perm, absent ⇒ 1.0 ⇒ bit-identical): a barrier lets both a foraging move and a natal disperser cross that edge only with probability = permeability, partitioning the grid into weakly-connected sub-patches (a hostile matrix). Built to test whether engineered heterogeneity gives a closed grid the asynchrony it lacks — measured: it does not. However the grid is partitioned, over ~a decade the predators still permeate the leaky edges and re-synchronise (collapse ~yr15–19); tightening barriers to near-isolation instead makes each block boom-bust independently. Sustained closed coexistence needs a narrow "just-right" connectivity window (Levins balance with staggered phases) that Huffaker hand-built and that this model does not reach generically. The barrier is a correct, reusable capability (fragmentation, corridors, connectivity), off unless set — but the robust route to coexistence remains openness (immig), not any closed-system construction. A barrier can also be made asymmetric per kind (Consumer.barrierCross, default 1 = the edge's base permeability): a multiplier on how well that kind crosses a barriered edge, the Huffaker case where prey slip across and the predator lags. Measured too — and it still does not give closed coexistence: the predator's high foraging-attempt rate leaks it across even a tight barrier within a couple of years (then it permeates and synchronises), and walling it off harder just starves it while the free prey escapes — no stable "one step behind" regime. A correct asymmetric-fragmentation capability, off by default; openness remains the route.

6.5The host API — what a game built on ECOSIM can see and do

Reference-implementation status: built. ecosim/host.py provides a Host facade over a (world, engine) pair implementing all four groups below. It exists because this section was previously an idea rather than an object — every capability was present but scattered, so a host would reach into world.cells[3].nutrient_layers[…] and a refactor would silently break it.

Two things the build settled. Events are polled, not wired in: the Host reads the engine's own records (world.dead, engine.events) behind cursors, so the engine genuinely stays unaware that anyone is listening. And every write is queued to a tick boundary via Engine.queue(fn), which runs it inside the tick so its ledger entries land in the audit window — this is not ceremony: a first implementation of plant() that mutated the world directly was rejected by the engine's own ConservationError: state was modified outside a tick, i.e. the guard below caught the host conjuring matter exactly as promised. verify_flux_budget() discharges 7's validation item 17: all five elements reconstruct to floating-point noise.

ECOSIM is an engine, not a game. The god game (see GODGAME_DESIGN.md) is one consumer of it, and there must be others. The boundary is this API. The rule: the engine never knows a game exists. No score, no player, no UI, no win condition inside EcoSimCore — those live entirely in the host. Everything the host needs, it gets here.

6.5.2Write — intervention (the god's hands, but also a scientist's experiment)

Every write is the same shape: a mass-conserving edit to a field, applied at the next tick boundary.

AddSubstance(cell|region, substance, Δmass)   // fertilize, pollute, salt, ash

Conservation is enforced even against the host. An AddSubstance call does not conjure matter — it draws from a named external reservoir (atmosphere, bedrock, outside-world) and the engine records it in the 4C ledger. So a god who fertilizes is visibly importing nitrogen from somewhere, and the balance sheet still closes. This is what stops a world-tending game from degenerating into free-matter cheating, and it makes the god's power feel like plumbing rather than magic.

6.5.5The rendering contract

The engine holds no meshes and no transforms. It publishes, per organism: position, height, diameter, crownArea, leafArea (4I.2a), leanVector, stage, species, stress. 8Model formalism

8.1The model as a dynamical system

Strip away the engineering and ECOSIM is one object: a discrete-time, spatially explicit, individual-based dynamical system with a shared continuum field, i.e. a map

        x(t+1) = F( x(t) ; θ , ξ(t) )
SymbolIsContents
xthe state vectorFields (per cell c, depth d, stratum a): nutrients[i][c][d], water[c][d], organicCarbon[c], organicNutrients[i][c], co2/o2[c], pH[c], T[c], decomposerBiomass[c], seedBank[s][c], elevation[c]. Everything else in this document — Liebig, Monod, Beer–Lambert, allometry — is a component of F. Stating it this way is not pedantry: it is what licenses Advance(100) (4A.3), reproducibility (13), and the entire analysis toolkit of 11–12, all of which assume F is a well-defined function.

8.2Integration scheme, and its honest limitations

F is an explicit (forward) Euler step: every rate is evaluated at the start of the tick and applied over Δt. This is the right choice — it is simple, it parallelizes, and it makes the two-phase apportionment (3.2.1) exactly conservative. But be clear-eyed about the price:

  • First-order accuracy. Local truncation error is O(Δt²), global O(Δt). Halving the timestep roughly halves the error. The model is not exact; it is convergent.
  • Conditional stability. Diffusion needs D·Δt/Δx² < 0.5 (4C). Fast reactions (microbial turnover, gas exchange) can be stiff — if a rate constant exceeds 1/Δt, explicit Euler oscillates or goes negative. Guard: cap every per-tick fractional rate at < 1 and clamp at 0.
  • Operator splitting. We apply uptake, then metabolism, then diffusion, sequentially rather than solving the coupled system. This introduces a splitting error of O(Δt) — acceptable, but it means the order of the 12 steps in 0.1 is part of the model definition, not an implementation detail. Changing the order changes the answer. Don't reorder it casually; if you do, re-run 8.3.
  • Where to upgrade if you need accuracy: the field diffusion (→ implicit / ADI, unconditionally stable) and the plant carbon balance (→ RK2). Neither is needed for a game; both may be needed for a publication.

8.3The timestep-convergence test (do this once, early — it is not optional)

Because rates are per-day (0.3.1), the ecology must not depend on ticksPerDay. Verify it:

Run the identical 50-year scenario at ticksPerDay = 6, 12, 24, 48, 96.
Plot a summary statistic (total biomass, mean soil N, species composition) vs Δt.
  • If the curves converge as Δt → 0, the model is sound and you may pick the coarsest Δt whose error you can live with. Report that error.
  • If they diverge, oscillate, or reorder the species ranking, you have a stability or unit-conversion bug — most often a rate that was tuned per-tick instead of per-day.
  • A model that gives a different forest at a different timestep is not a model of a forest; it is a model of its own timestep. This test is the difference between a simulation and an animation, and it is the first thing a reviewer will ask for.

8.4Stochasticity — report distributions, not anecdotes

The model is stochastic (dispersal, mutation, disturbance, establishment). A single run is one sample from a distribution, and its trajectory is not a result. Two runs of the same forest with different seeds can plausibly end up as different forests — and that variance is itself a finding (it measures how contingent the ecosystem is).

Therefore: for any claim about model behaviour, run an ensemble (≥ 20 seeds) and report the median and interquartile range, not one trajectory. The one case where a single run is the right unit is the determinism test (13): same seed → bit-identical result.

Distinguish carefully:

  • Aleatory uncertainty — the model's own randomness. Handled by ensembles.
  • Epistemic uncertainty — we don't know the true parameter values. Handled by 11.

9.3The single most important caveat

ECOSIM is a mechanism-exploration model, not a predictive one. It is built to answer "what patterns follow from these rules?" — succession, coexistence, soil-building, disturbance response. It is not calibrated to forecast the biomass of a specific real forest in 2075, and it should never be presented as if it were. The parameters (11) are plausible, not measured; the processes (9.2) are incomplete; the resolution (A1) is coarse. Within those bounds it is a legitimate scientific instrument. Outside them it is a very pretty video game.

9.4Roadmap — what is built, and what is not yet

The model is grown one mechanism at a time, each landed off-by-default and bit-identical to the golden oracle (13.4). What exists today and what is deliberately still open:

Landed — the plant engine (carbon economy, 3D light/root competition, water & hydraulics, multi-nutrient soil with a conserving ledger, phenology & the seed/seedling banks, demography with density dependence); disturbance & fire, including the patch-gap disturbance that closes the canopy (4L.1) — advance-regeneration succession plus local gaps now produce a genuine closed canopy on every forest biome; the heterotroph layer of 4Q (general condition; herbivory with a growth–defense trade-off; the two-tier consumer interface with six tissue attacks and bank-vs-rain granivory; discrete animal agents with births, longevity, foraging mobility and a second predator trophic level); the mycorrhizal symbiosis and shared network of 4M — the "share" half of the founding brief, whose carbon trade is conditional on soil fertility and reverses sign along it; and deadfall (4G.5), which turns a dead tree from a number added to its own cell into a trunk lying across the ground, crushing what it lands on and nursing what grows on it once it has rotted; and rocks (4G.4), which lets ground be partly bare stone and makes an outcrop droughty — but only when the rain is episodic.

Open, in rough priority —

  1. The 2D→3D spatial engine. Foundation + two couplings landed — cells now sit on a real cols × rows grid and are coupled across it: cross-cell seed dispersal (4W) turns the grid into one connected landscape (a species colonizes outward from a single seeded cell), and 2D animal movement (4Q.4) lets a forager walk the grid toward food. Both measured and conservation-exact — and the 2D movement's ecological payoff is measured: predator–prey persistence extends 7–13× on a grid versus a well-mixed cell of equal area (Huffaker refugia, 4Q.4). A third coupling — a predator-tracking kinesis (forageInterference, 4Q.4) — was built and measured to test whether it turns that prolonged persistence into sustained cycles: it un-clumps the predators as designed but does not stabilise the system, a clean negative (4Q.4). The PLANT-side couplings then landed: inter-cell edge shade (edgeShade, §B2) lets a tall crown near a cell boundary shade the neighbour (measured to drop the under-crown light of an empty adjacent cell to deep shade in the strip beneath the overhanging crowns — a real forest-edge effect — while the interior is untouched), and downhill water routing was upgraded from the old 1D chain to true 2D grid edges, so water drains ridges and pools in valleys: on a row-graded 3×3 slope a 206× ridge-to-toe moisture catena emerged, conservation-exact. The grid now shares light AND water across cells, so topography drives a real moisture mosaic. The vertical axis then landed for the soil: with nSoilLayers > 1 both water and nutrients are apportioned per layer against each plant's rootDepth (4H.2), each flux enters at its physical depth (litter on top, weathering at the base, leaching cascading down), and the textbook profile — N surface-held, P/K rock-held — emerges rather than being imposed. The root system is now complete — the lateral footprint, dynamic foraging and the 4H.3 archetypes all landed, and the reason vertical coexistence never appears is understood (in a recycling ecosystem flux beats stock, 4H.2). The host API of Part I is built (6.5, ecosim/host.py). The remaining "air voxels" item is withdrawn, not outstanding: discrete air voxels would make the light model less accurate (they restore symmetric within-layer competition), so the canopy keeps its continuous-height physics with nStrata as reporting only — see 1A. The real gap in that model, a sun nailed overhead, is closed by sunAngleShade (4G). LOD is explicitly not a simulation task — it is host-side rendering (form vs function); a headless oracle's per-plant state already is the low-detail representation, so there is nothing to switch down.
  2. Per-kind animal demographics — landed. Every world-level agent rate (birth size and rate, senescence, starve/heal, move, interference) now has an optional per-consumer override, so predator and prey can run on their own schedules (4Q.4). Measured: the capability works and strongly reshapes the dynamics, but — like the tracking kinesis — separate clocks alone do not rescue coexistence (a long-lived predator eats the prey to extinction). A precondition for cycles, not the cause.
  3. Predator–prey coexistence — resolved: it was openness, and it is now demonstrated. Five per-agent candidates (tracking, per-kind demographics, a bigger landscape, a prey refuge, and the Type II → Type III functional-response shape, 4Q.4) were each measured to not deliver sustained cycles in a closed grid — which is correct ecology, exactly as Huffaker found (small simple mite universes died; only a large complex one with dispersal barriers and rescue oscillated). The capstone diagnosed the missing ingredient as openness, and open-boundary immigration (Consumer.immig, 4Q.4) confirms it: one-sided predator immigration is destabilising (a subsidised predator grinds the prey extinct), but two-sided immigration produces the model's first sustained coexistence — both species oscillate in bounded cycles for the full run on both seeds, neither going extinct. So the answer was a boundary condition, not a trait. Local natal dispersal (Consumer.disperse, 4Q.4) then added the metapopulation's internal coupling: alone in a closed grid it only synchronises the patches (collapse — confirming persistence needs openness, not reshuffling), but composed with the immigration rescue it spreads the otherwise-clumped predator across the landscape, making a proper spatially-extended metapopulation. And the last question — can a large closed grid self-sustain without external input? — was measured across five regimes (10×10, both seeds): no. However weak or strong the dispersal, however fast the predator, with interference on, or seeded as a fully-scattered metapopulation, the mobile predators end up synchronised across the uniform grid (their kinesis tracks a globally-reachable prey field) and collapse on the same ~yr10–17 schedule as the 5×5. Spatial asynchrony does not emerge from a uniform landscape — faithful to Huffaker, who had to engineer dispersal barriers to get it. So closed self-sustaining coexistence needs a new axis, landscape heterogeneity / dispersal barriers (a hostile matrix, per-cell habitat quality, movement-resisting edges) that hold local phases apart; openness remains the single-parameter route. That axis was then built and measured too: per-edge movement/dispersal barriers (World.set_barrier, 4Q.4) partition the grid into weakly-connected blocks — and a closed partitioned grid still collapses (~yr15–19), because barriers slow but do not stop the predators permeating and re-synchronising, while tightening them to near-isolation just makes each block boom-bust independently. Sustained closed coexistence needs the narrow "just-right" connectivity window (Levins balance + staggered phases) that Huffaker had to hand-build and that this model does not fall into generically. Net: the whole thread converges on one robust result — coexistence comes from openness (immig), reliably and with one parameter; no closed mechanism reproduces it without fine engineering. Edge-only immigration (World.immig_edge, 4Q.4) was then added as the physically-faithful open boundary — coexistence still holds through perimeter rescues, though at rare rescue rates the entry geometry is a minor ecological lever. Asymmetric per-kind barrier permeability (Consumer.barrierCross, 4Q.4) — the Huffaker prey-escape asymmetry, the most promising closed lever left — was then built and measured: it too does not give closed coexistence (the predator leaks across even tight barriers and synchronises, or is walled off and starves as the free prey escapes). The closed-system question is thus exhausted; the route is openness. Open follow-ons: the discrete-kill / heterogeneity refinements.
  4. Discrete-kill predation & pathogens — landed. Whole-individual kills (Consumer.killWhole, 4Q.4): a predator kills whole prey at the functional-response rate — measured to match the continuous kill rate while leaving no wounded survivors, and to destabilise the predator through feast-or-famine intake. And the host-specialist pathogen (pathogenVirulence, 4W) makes CNDD mechanistic: a per-cell, per-species soil inoculum builds under conspecific hosts, decays, and kills their seedlings — crucially with MEMORY, so it persists after the adults die (a recruitment ghost the instantaneous basal-area census could not express). Both off-by-default, bit-identical, conservation-exact.
  5. Seasons, latitude & weather — latitude landed. The day-length driver's hardcoded amplitude (an implicit ≈41 °N imposed on every biome) is replaced by the real sunrise equation under latitude (4A.2), validated against published day lengths and yielding polar day/night from the clamp. Measured on the boreal biome at its true 62 °N: the light climate is transformed (midwinter PAR falls 24×) and early succession becomes markedly more realistic — birch and aspen rise from a token 4 %/4 % to a genuine 18 %/10 % pioneer cohort — but NPP barely moves, because in a boreal winter the light and temperature limits are redundant (it is already too cold to fix carbon). Stochastic weather landed too (weatherVar/weatherMemory, 4A.2): an autocorrelated, timestep-invariant Ornstein–Uhlenbeck temperature anomaly. Measured across two seeds, annual NPP variability roughly triples-to-quintuples (CV 2–5 % → 11–13 %) and the worst year falls to ~55 % of the best — real good and bad years, the signal disturbance timing and masting need. A predicted storage effect (fluctuations relaxing the chronic monocultures) was tested and refuted: it appeared on one seed and vanished on a second, because the anomaly never reverses a hierarchy that late succession decides on shade tolerance. Rainfall variability landed too (rainVar, 4A.2), giving multi-year droughts — and with it the best emergent result of the climate work: mean-preserving rainfall variability reduces mean productivity by 12–13 % in a water-limited biome (Jensen's inequality on a saturating water response), while barely touching an energy-limited one, and the worst year falls to 3–9 % of the best. Item 5 is complete.
  6. The Mediterranean / fire-maintained biome — resolved. The one biome whose climax the model got wrong (a boreal Pinus sylvestris monoculture). After nine physiological/climatic levers had been measured and refuted, the cause turned out to be the same as the temperate_conifer biome: an incoherent species pool — the boreal P. sylvestris and temperate Q. robur were still stocked beside the two natives and won the too-cool climate. The coherent-flora fix (drop the intruders, restock Q. suber and Q. coccifera for a real evergreen-oak / pioneer-pine / resprouter community), plus a modest drying, produces the correct fire-free climax — a Q. ilex-dominated sclerophyll forest (ilex ~70 %, cork oak ~20 %, Aleppo pine a ~10 % relic) with NPP in the Mediterranean range. No new mechanism, no tuning of the sort — the flora was the bug (9.3).
  7. Mycorrhizal symbiosis & the shared network — landed, and half of it failed usefully. The oldest unbuilt section in the spec, and the missing half of the founding brief: trees were specified to "compete, share, and so on", and only competition was ever built. The symbiosis (4M.1) is a real trade — the plant buys colonisation with a cut of gross assimilation, gets a raised Vmax and a lowered Km, and pays in carbon that would otherwise have been wood. It is conditional without a rule making it so: what a plant pays scales with how empty its scarcest reserve is, so a well-fed plant stops paying. Measured on a phosphorus gradient with both seeds agreeing at every point, the partnership raises stand biomass 110 % on the poorest ground and costs 25 % on the richest, crossing over between 1.4 and 6.0 g P m⁻², and the Liebig factor predicts the crossing exactly: it pays when (1 − phi) > mycoTax. Colonisation falls 57–60 % from the poorest site to the richest, so fertilizing a forest shrinks its network. The network (4M.2) is built and moves real carbon, but its promised payoff — shaded seedlings living on a subsidy — does not appear, and the reason is the useful part: nothing in a suppressed understory dies of carbon starvation. Suppression is a shade-keyed hazard (4N), so a carbon subsidy cannot answer it however much arrives. Delivering that payoff is a change to mortality, not to the network. Two further open items came out of the same work: 4M.2's own pseudocode had to be corrected (there is no spare NSC in this engine to share — the source has to be the mycelium), and the default weathering rate turns out to be one to two orders of magnitude above published rock-P release, which leaves every biome preset effectively P-replete and is logged for calibration rather than quietly changed.
  1. Deadfall, coarse woody debris & nurse logs — landed, with the section's headline claim demoted by measurement. A dead tree used to be a number added to the cell it stood in. It is now an object with geometry: the trunk falls toward the biggest gap, lies across as many cells as the tree was tall, crushes what it lands on, and slowly rots into the litter pool while changing the seedbed it covers (4G.5a). Two results are solid — crush is size-selective (16.8 % of a seedling against 9.5 % of a 100 kg tree, over 1000 replicate falls) with an emergent domino on top, and the nurse log reverses sign with decay state (recruitment −41 % under a fresh trunk, +74 % under a rotted one, four seeds agreeing individually). One is not: the "large, slow-decomposing pool" the section leads with changes almost nothing, because organicC in this model already turns over at k ≈ 0.042 yr⁻¹ and there is nothing for a fast/slow contrast to be a contrast against — a calibration observation about the litter pool, logged rather than papered over by slowing the wood. A log matters because it is a place, not because it is slow. Still open in 4G at the time: rocks (4G.4) and phototropism (4G.3), both since built; the suspended trunk, which needs a per-log object, remains.
  1. Rocks & obstacles — landed, with one claim confirmed and one only half. Ground can now be part bare rock (4G.4a), modelled as the absence of soil so it never touches the ledger: it shrinks water storage, exchange capacity and establishment sites, and filters who may establish. The headline result is an interaction nobody designed: rock alone is not droughty — under continuous rain a smaller store is simply full more often, and measured moisture actually rose with rock — but the same 90 %-rock cell under episodic rain (same annual total, 20-day interval) goes to zero moisture and zero stems while bare soil still carries a stand. Storage capacity only matters when there is a gap to store across. The lithophyte filter needed the third bullet — rooting volume — before it could do more than nudge: gating establishment alone let an intolerant tree that got in grow as though the rock were absent. Scaling uptake by the rooted soil fraction, through the same tolerance expression, turns a nudge into an outcrop community: the tolerant species holds 78 % and 86 % of biomass at 90 % rock (+31 points on both seeds), with the intolerant one down 58–69 % in absolute mass. A quieter result worth keeping: in a moist climate the outcrop is not sparser, merely differently composed — total biomass and stem count barely move, because a species adapted to the substrate fills the space. Rock decides who grows; rock plus episodic rain decides whether anything grows. Still open in 4G: the suspended trunk of 4G.5.
  1. Phototropism — landed, and honestly a small result. Crowns now drift up the light gradient and cast shade from where they actually are, with the stem staying put (4G.3a). For an INDIVIDUAL the effect is life or death — a staged focal tree goes from 0 to 199.7 kg C once its lean clears a neighbour's crown — but the payoff is a step, not a slope, because 4G.1's shading is a binary disc test that partial overlap cannot soften. At stand scale it does not aggregate: two seeds disagree in sign on biomass and stem count, and the only quantity that replicates is LAI (+11.5 %, +6.9 %) — crowns that can move sideways pack the canopy more completely. Making the individual edge aggregate would need graded shade, a change to B2's core light model, recorded as an open decision rather than taken. 4G.5 gains its first fall cue for free: a leaning trunk now falls the way it leaned.

Each is an added mechanism, not a re-tuning — the discipline that keeps the model honest (9.3).

10Provenance — where every equation comes from

Nothing in this model is invented. Each core equation is a standard, published formulation, chosen because it is the simplest form that captures the mechanism. This section gives, for each: the equation, the derivation (why it has that shape), and the literature it comes from — so a researcher can check our work, and a developer can understand what they're implementing rather than transcribing symbols.

10.1Beer–Lambert light attenuation — L = L₀·exp(−k·LAI)

Derivation. Consider light passing down through a thin layer of canopy of leaf-area increment dLAI. The fraction of photons intercepted is proportional to the leaf area they encounter: dL = −k·L·dLAI. That is a first-order linear ODE; separating and integrating gives L(LAI) = L₀·exp(−k·LAI). The exponential is not a curve-fit — it is the unique consequence of "each leaf layer removes a constant fraction of what reaches it." k bundles leaf angle and clumping (k ≈ 0.5 for randomly-oriented leaves — the value falls out of the geometry of a sphere). Source: Monsi & Saeki (1953), the foundational paper of canopy light modelling; used unchanged in essentially every forest model since.

10.2Michaelis–Menten / Monod uptake — U = Vmax·C/(Km+C)

Derivation. Root nutrient uptake runs through a finite number of membrane transporter proteins. Let [T] be free transporters and [TC] transporters bound to a nutrient ion. At quasi-steady state, binding and unbinding balance, and solving for [TC] as a fraction of total transporters gives the rectangular hyperbola U = Vmax·C/(Km+C). Vmax is "all transporters saturated"; Km is the concentration at which half are occupied. So the saturating shape is a consequence of a finite number of doors, not an assumption. This is why Km means what 3.2 claims it means: a species with a low Km has high-affinity transporters that keep working at low concentration — a scavenger. That is a real, measurable physiological trait, not a game-balance knob. Source: Michaelis & Menten (1913) for enzymes; Monod (1949) for microbial growth; Epstein & Hagen (1952) applied it to plant-root ion uptake. Standard in every soil-plant model.

10.3Liebig's Law of the Minimum — φ = min_i r_i

Rationale. Growth requires all essential nutrients in fixed proportions. You cannot substitute nitrogen for phosphorus, so the scarcest one relative to need sets the ceiling — the classic "barrel with the shortest stave." This is non-substitutability, and it is why the aggregator is min() rather than a sum or product. Known criticism (state it honestly): the sharp min() is too abrupt; real plants show smooth co-limitation, and multiple resources often co-limit simultaneously. That is precisely why limitationMode (3.3) offers a multiplicative alternative — the truth is usually between them. Source: von Liebig (1840); the co-limitation critique is Bloom, Chapin & Mooney (1985) and Danger et al. (2008).

10.4The Q10 temperature response — R ∝ Q10^((T−Tref)/10)

Derivation. It is a linearized Arrhenius law. True kinetics give k ∝ exp(−Ea/RT); over the narrow biological range (0–40 °C) this is well approximated by a constant proportional increase per 10 °C, which is Q10. Q10 ≈ 2 for respiration means respiration doubles for every +10 °C — a huge effect and the main reason warming can flip an ecosystem from a carbon sink to a carbon source. Source: Van 't Hoff; in ecology, Lloyd & Taylor (1994) (who note Q10 itself declines with temperature — a refinement we skip).

10.5Allometry — h = a·B^p

Rationale. Organisms cannot scale isometrically: doubling every dimension multiplies mass by 8 but cross-sectional support area only by 4, so a scaled-up tree would crush itself. Mechanical stability and hydraulic transport both force power-law relations between mass, height and diameter. Metabolic scaling theory (West, Brown & Enquist) derives exponents from the geometry of branching transport networks and predicts h ∝ D^{2/3} and metabolism ∝ M^{3/4}. Why we use them without apology: these relations are among the best-supported quantitative regularities in all of biology, they are measured for thousands of species, and they let us derive four expensive geometric quantities from one cheap state variable. Source: Niklas (1994); West, Brown & Enquist (1997, 1999); Enquist et al. (1998). Caveat: the universality of the 3/4 exponent is genuinely contested — treat q and p_h as fitted parameters, not constants of nature.

10.6Surface-vs-volume growth limitation (4I.3)

Derivation. Carbon income is proportional to intercepted light, hence to leaf area (∝ B^{2/3} for an isometric object). Carbon cost is maintenance of living tissue, proportional to mass (∝ B^1), plus a hydraulic transport term rising with height. Since the exponent of cost exceeds that of income, there necessarily exists a size B* where dB/dt = 0:

A·B^{2/3} = m·B  ⟹  B* = (A/m)^3

Growth therefore asymptotes for purely geometric reasons — no arbitrary maxSize cap is needed, and none is used. This is the same argument that explains why organisms have maximum sizes at all, and it is why the 4P worked example decelerates. Source: von Bertalanffy (1957) — the original derivation of the sigmoid growth curve from exactly this surface/volume asymmetry. Our 4I.2 logistic growth curve is his result, re-derived from the energy budget rather than assumed.

10.7Stomatal trade-off & water-use efficiency (4J)

Photosynthesis and transpiration share one pore, so WUE = P/Tr is bounded. Optimal stomatal theory says a plant should open its stomata to the point where the marginal carbon gain equals the marginal water cost. Source: Cowan & Farquhar (1977) (optimal stomatal behaviour); Farquhar, von Caemmerer & Berry (1980) (the standard biochemical photosynthesis model — our Monod-on-CO₂ is its simplified, Rubisco-limited branch); Sperry et al. (2016) for hydraulic-failure mortality.

11Calibration, sensitivity & uncertainty

The model has on the order of 40 global + 40 per-species parameters. That is a lot of freedom, and freedom is not a virtue — "with four parameters I can fit an elephant" (von Neumann). This section is how we stop the parameters from being an excuse.

11.1A parameter is one of three things — label each one

11.2On the calibration constants c1, c2_τ (4I.6) — a warning

The earlier draft framed these as "constants we might have missed, found by hand." Let me be blunt about what they are: c1 is an unexplained additive carbon source. It is free growth from nowhere, and it will:

  • break carbon conservation (4C) unless you explicitly book it against a pool;
  • absorb the symptoms of a missing mechanism, so you never find the mechanism;
  • be the first thing a reviewer attacks.

Keep them, but govern them:

  1. Default 0, and prefer they stay 0. They are a last resort, not a tuning layer.
  2. Bound them: |c1| < 0.05 · P (5 % of gross assimilation). A larger value is a diagnostic that a process is missing — go find it in 9.2.
  3. If c1 must be non-zero, book it as a real flux (e.g. draw it from E or from the atmosphere) so mass still balances.
  4. Report them. A published c1 is a confession that becomes an invitation for someone to explain it. A hidden c1 is a fudge factor.

Prefer fixing structure to fitting constants. Nearly every "missing residual" you will hit has a name in 9.2.

11.3Fitting the fitted parameters

Do not hand-tune. Define a loss over emergent observables and minimize it:

Loss(θ) = Σ_k w_k · [ (sim_k(θ) − obs_k) / σ_k ]²     // k over the 12 target patterns
  • Method: for a cheap model, Latin-hypercube sampling + Nelder–Mead or a genetic algorithm. For uncertainty, Approximate Bayesian Computation (ABC) or MCMC — both work with a stochastic simulator and give you a posterior distribution over parameters, not a single brittle point estimate. That posterior is far more honest, and it feeds directly into ensemble runs (8.4).
  • Fit to patterns, not to trajectories — see 12.
  • Identifiability: with 80 parameters and a handful of target patterns you are massively under-determined. Many parameter sets will fit equally well (equifinality — Beven's term, and the central problem of environmental modelling). Accept it: report the ensemble of acceptable parameter sets and the spread of their predictions, rather than pretending one set is "the" calibration.
  • Never fit and validate on the same pattern. Hold some out.

11.4Sensitivity analysis — do this before you calibrate

You cannot calibrate 80 parameters. You can calibrate the 8 that matter. Find them:

  1. Morris screening (elementary effects) — a cheap first pass, O(10·p) runs, that sorts parameters into "negligible", "linear", "nonlinear/interacting". Run this first, always. It will typically show that most parameters barely matter and a handful dominate — and it costs almost nothing.
  2. Sobol variance decomposition — for the survivors, quantify what fraction of the variance in each output each parameter explains, including interaction terms (S_i first-order, S_Ti total). Expensive (thousands of runs) but definitive.
  3. Report a sensitivity table per key output (biomass, diversity, soil carbon, time-to-canopy-closure). It tells a reader which numbers to trust and which to argue about.

This also has a direct engineering payoff: parameters with near-zero Sobol index can be fixed at their default and removed from the tuning surface — which is exactly the short list of knobs a game designer actually wants exposed.

11.5Uncertainty propagation

Report every headline result as a distribution, from three stacked sources: parameter uncertainty (the 11.3 posterior) × stochastic variability (8.4 seeds) × structural uncertainty (9 — the one you cannot quantify, only disclose). If the conclusion survives all three, it is a finding. If it doesn't, it was an artefact.

12Validation — what would prove this model wrong

A model that cannot fail cannot be trusted. Validation here does not mean "the forest looks nice." It means: the model was built from local, individual-level rules, and it must independently reproduce system-level patterns that were never coded in. That is the whole point of a mechanistic model, and it is the only real evidence that the mechanisms are right.

This is pattern-oriented modelling (Grimm et al. 2005): use multiple, weak, independent patterns simultaneously. Any single pattern can be fitted by a wrong model; a handful of unrelated patterns, matched at once, is very hard to fake.

12.2How to run it

V10 is a unit test — run it in CI on every commit. V1, V8, V9 are controlled single-cell or single-stand experiments and should also be automated. V2–V7 need century-scale ensemble runs (8.4) and are the "release gate."

Crucially: calibrate on some patterns and validate on the others (11.3). A model tuned to hit all ten proves nothing.

12.3What we deliberately do not claim

We do not claim to predict a specific real forest, a specific species' biomass, or a future climate response. See 9.3. The validation above establishes that the model is structurally plausible and internally sound, which is a real and sufficient claim for what this is.

13Reproducibility & scientific reporting

A result no one can reproduce is not a result. The determinism of 4A is not just a feature for fast-forward — it is what makes this instrument scientific.

13.1What must be recorded with every run

run_manifest.json
  ecosim_version   : git commit SHA of the simulator
  config_hash      : SHA-256 of the fully-resolved EcoSimConfig + all SpeciesDefinitions
  rng_seed         : the master seed
  fidelity_mode    : full-detail | aggregate    (4A.3 — results are NOT comparable across modes)
  ticks_per_day    : the integration timestep    (8.3 — the ecology must not depend on it)
  spin_up_years    : discarded warm-up period    (13.2)
  platform         : OS / compiler / float mode  (see the determinism caveat below)

Determinism caveat (be honest about it): bit-identical reproduction across different machines requires care — floating-point reassociation, -ffast-math, SIMD width and parallel-reduction order can all change the last bits, and in a chaotic system last bits grow into different forests over a century. Guarantee same-machine, same-binary determinism unconditionally; for cross-platform reproducibility, fix the reduction order, disable fast-math in the core, and consider fixed-point or Kahan summation for the conservation-critical sums.

13.2Spin-up (the step everyone forgets)

Never start measuring from the initial condition. A hand-initialized soil is not an equilibrium soil; the first decades of any run are the model relaxing away from your arbitrary starting numbers, and that transient is an artefact, not ecology.

Run the model with no disturbance until soil carbon and nutrient pools plateau
(typically 10²–10³ simulated years). THAT state is the initial condition. Discard the
transient. Report the spin-up length.

Symptomatically: if your "results" are dominated by what happens in the first 20 years, you are reporting your own initialization.
